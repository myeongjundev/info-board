# T04 — 결정과 현재 상태

**이 파일이 상태를 적는 유일한 곳이다.** 다른 문서는 여기를 링크만 한다.
T02 에서 난이도 실험 하나가 세 문서에 각각 미시작·미통과·통과로 적혀 있었다.
같은 일을 반복하지 않는다.

마지막 갱신: 2026-08-27

---

## 확정 — 데이터 소스

**Stack Exchange API · 스택오버플로 일별 신규 질문 수**

```
GET https://api.stackexchange.com/2.3/questions
      ?site=stackoverflow&fromdate=<UTC>&todate=<UTC>&filter=total
→ 200  application/json  access-control-allow-origin: *  인증 키 없음
→ {"total": 42}
```

### 왜 이것인가

같은 주(8/17~8/23)를 연도별로 실측했다.

| 연도 | 신규 질문 |
|---|---:|
| 2019 | 30,979 |
| 2022 | 24,985 |
| 2024 | 6,165 |
| 2025 | 1,219 |
| **2026** | **402** |

7년 만에 98.7% 감소. 이 값은 통계가 아니라 **개발자가 사람에게 묻지 않게 된
시점의 기록** 이다. 그리고 그 변화의 한가운데에서 업계에 들어가는 사람이 만든다.

**"이 숫자를 어떻게 읽어야 하는가" 에 대한 답이 데이터 안에 있다.** 다른 후보들은
임계선이 없어 고민했는데, 여기서는 같은 API 로 2019년을 부르면 역사가 기준이 된다.

### 조건 충족

| 조건 | 상태 |
|---|---|
| 공식 문서 · 사용 조건 | api.stackexchange.com/docs 공개 |
| 인증 키 | **불필요** |
| CORS | `*` — 브라우저 직접 호출 가능 → 카드 3 의 timeout·offline 이 실제로 재현된다 |
| 단위 | 건 |
| 기준 시각 | `fromdate`/`todate` UTC 로 명시 |
| 날짜별 값 하나 | 성립 |
| 원자료 주소 공개 | 그대로 열림 |

### 알고 시작하는 약점

1. **값이 작아 일간 변동이 크다.** 실측 32~78건. 42 → 78 은 +86% 지만 실제로는
   요일 차이다. 전일 대비만 보여주면 노이즈를 정보인 척하는 것이다.
   → 전일 대비를 기본으로 두되 **7일 이동평균을 함께** 표시하고, 값이 작다는 사실을
   화면에 명시한다.
2. **일반 대중성은 낮다.** 비개발자는 스택오버플로를 모른다. 심사자가 개발자라는
   점에서 감수한다.
3. 2026년 수치가 API 특성이 아닌 실제인지 **한 번 더 다른 방법으로 교차 확인** 한다.

## 설계 불변식 — 코드보다 먼저 정한 것

> **화면에 보이는 값·단위·출처·기준시각·조회시각은 언제나 하나의 응답 객체에서
> 나온다. 절대 따로 전달하지 않는다.**

```js
Reading = { value, unit, sourceUrl, sourceLabel, observedAt, fetchedAt }
```

`observedAt` 은 자료가 가리키는 날, `fetchedAt` 은 내가 조회한 시각이다. 묶어서만
다루면 "값은 새 것인데 시각은 옛 것" 이라는 거짓말이 구조적으로 불가능해진다.
카드 3 의 "정상값이 없을 때 값이 있는 것처럼 표시하지 않는다" 도 여기서 따라온다 —
`Reading` 이 없으면 숫자 자리에 넣을 것이 아예 없다.

T03 의 "미리보기와 다운로드를 같게 만들지 않고 같은 것으로 만든다" 에 대응하는 결정이다.

```
state ∈ FRESH | STALE | EMPTY
fault ∈ TIMEOUT | AUTH | RATE_LIMIT | OFFLINE | SCHEMA
```

`STALE` 은 마지막 정상값을 보여주되 `fetchedAt` 을 **절대 now 로 갱신하지 않고**
경과 시간을 함께 쓴다. `EMPTY` 는 숫자 자리에 `—`.
