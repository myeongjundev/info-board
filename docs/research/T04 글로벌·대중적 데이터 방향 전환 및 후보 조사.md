# 1. 현재 방향 전환

T04의 데이터 주제를 여러 방향으로 탐색했다.

지금까지 검토한 대표 후보:

```text
나무위키
KOBIS 일별 박스오피스
YouTube KR
Wikipedia
Crossref
USGS 지진
NOAA 우주날씨
NASA EONET
```

각각 장점은 있었지만 최종 주제로 결정할 만큼 마음에 들지는 않았다.

따라서 이번에는 방향을 바꾼다.

# 새로운 탐색 방향

> **GLOBAL + POPULAR + DAILY**

즉,

> **전 세계 사람들이 오늘 실제로 무엇을 보고, 읽고, 이야기하고, 플레이하고, 만들고 있는가?**

를 보여주는 데이터로 범위를 넓힌다.

---

# 2. 왜 글로벌로 전환하는가

처음에는 한국 데이터를 우선적으로 찾았다.

예:

```text
나무위키
KOBIS
YouTube KR
한국어 Wikipedia
```

하지만 한국 데이터만 고집하면 다음 문제가 있었다.

```text
공개 API 부족
API Key 필요
CORS 문제
데이터 의미가 애매함
공식 endpoint 부족
날짜별 비교 어려움
```

반면 글로벌 서비스는 공개 데이터 생태계가 훨씬 넓다.

따라서 이제:

```text
Korea Only
```

라는 조건을 제거한다.

대신:

```text
Global
Popular
Understandable
Daily
Public
```

을 중요하게 본다.

---

# 3. 이번 탐색에서 가장 중요한 기준

단순히 기술적으로 좋은 API를 찾는 것이 아니다.

다음 질문을 먼저 한다.

> **심사자가 사이트를 처음 열었을 때 15초 안에 이 숫자가 무엇인지 이해할 수 있는가?**

예를 들어:

```text
3.7 × 10^-5 W/m²
```

는 과학적으로 훌륭한 데이터지만 설명이 필요하다.

반면:

```text
1,482,921
PLAYERS ONLINE
```

은 바로 이해할 수 있다.

또:

```text
8,421
TOP STORIES POINTS
```

도 어느 정도 직관적으로 이해할 수 있다.

따라서 앞으로는 **데이터의 대중성 및 즉시 이해 가능성**을 중요하게 평가한다.

# 4. 새로운 핵심 질문

```text

```

이를 다음 다섯 영역으로 나눈다.

```text

```

## INTERNET

```text
오늘 사람들은 무엇을 이야기하고 있는가?
```

## CONTENT

```text
오늘 사람들은 무엇을 보고/읽고 있는가?
```

## DEVELOPMENT

```text
오늘 개발자들은 무엇을 만들고 있는가?
```

## ATTENTION

```text
오늘 세계 사람들의 관심은 어디에 있는가?
```

# 5. T04 데이터 소스 필수 조건

새 후보를 찾을 때 다음 조건을 최대한 만족해야 한다.

```text
1. 공식 데이터/API

2. API Key 없음

3. CORS 허용

4. JSON 또는 구조화 데이터

5. 값의 단위 명확

6. timestamp/date 명확

7. 날짜별 하나의 값 정의 가능

8. 어제와 오늘 비교 가능

9. 원자료 URL 공개 가능

10. GitHub Pages 사용 가능

11. GitHub Actions 수집 가능

12. Secret = 0
```

추가적으로 매우 중요:

```text
13. 일반인이 숫자의 의미를 바로 이해할 수 있음

14. 매일 다시 들어와 볼 이유가 있음

15. UI 디자인 소재가 좋음

16. 포트폴리오 설명이 쉬움
```

# 8. 게임 데이터가 매력적인 이유

게임 동접자는 설명이 거의 필요 없다.

```text
1,482,921 players
```

을 보면 누구나 의미를 이해한다.

또한 매일 숫자가 변한다.

예:

```text
AUG 25

1,382,921 players

↓

AUG 26

1,482,921 players

▲ +100,000
▲ +7.2%
```

T04의:

```text
현재값
단위
날짜
출처
조회시각
이전값
차이
방향
```

을 표현하기 매우 좋다.

---

# 9. 게임 데이터의 문제

Steam Web API 중 상당수는 API Key를 요구한다.

따라서 아직:

```text
Steam = 최종 확정
```

이 아니다.

반드시 확인해야 한다.

```text
공식 Keyless endpoint 존재 여부

CORS

현재 플레이어 수 제공 여부

timestamp

rate limit

GitHub Actions 호출 가능 여부
```

조건을 만족하지 못하면 Steam은 후보에서 제거한다.

비공식 Steam scraper 등을 사용해서 억지로 구현하지 않는다.

# 10. 후보 B — INTERNET IS TALKING

Hacker News 공식 API를 활용하는 방향.

Hacker News는 공식 Firebase API를 제공한다.

대표 endpoint:

```text
/topstories.json

/newstories.json

/beststories.json
```

개별 story에는 다음 정보가 있다.

```text
title
score
time
descendants
url
```

따라서 오늘 인터넷 기술 커뮤니티에서 가장 관심받는 이야기를 표현할 수 있다.

# 12. Hacker News를 T04에 맞게 변형

단순 Top Story 사이트로 만들지 않는다.

메인 값 하나를 정의한다.

예:

# INTERNET HEAT

Top 10 Hacker News Story의 score 합계.

```text
#1  1842
#2  1284
#3  1012
#4   921
#5   816
...
```

계산:

```text
SUM(top 10 score)

= 8,421 HN points
```

화면:

```text
INTERNET HEAT

8,421
HN POINTS

▲ +930
▲ +12.4%

vs yesterday
```

# 13. INTERNET HEAT의 장점



# 14. INTERNET HEAT의 주의점

`INTERNET HEAT`는 Hacker News 공식 지표가 아니다.

즉:

```text
Hacker News 공식 인터넷 열기 지수
```

라고 표현하면 안 된다.

정확한 표현:

> **프로젝트에서 정의한 Top 10 Hacker News score 합계**

또는:

> **Top 10 Story Combined Score**

정도로 표현한다.

# 16. WORLD READING의 장점

굉장히 대중적이다.

Wikipedia는 누구나 알고 있다.

그리고:

```text
18,492,813 views
```

라는 숫자도 설명이 거의 필요 없다.

매일 1위 문서가 달라질 수 있기 때문에 정보판으로서 재미도 있다.

---

# 17. WORLD READING의 단점

Wikimedia Pageviews API는 이미 잘 알려져 있다.

따라서:

```text
기술적 독창성
```

은 상대적으로 낮다.

하지만 디자인과 데이터 표현을 잘하면 충분히 보완 가능하다.

예:

```text
WORLD ATTENTION

WHAT THE WORLD
COULDN'T STOP READING

#01
XXXXXXXX

18.4M VIEWS
```

처럼 정보 디자인을 강하게 가져갈 수 있다.

# 20. GitHub 후보의 장점

개발자 포트폴리오라는 점에서 스토리가 좋다.

예:

> **GitHub 공개 이벤트를 일정 시점에 수집하고 이벤트 타입별 활동량을 분석하는 글로벌 개발 활동 정보판**

기술적으로:

```text
REST API
Rate Limit
Failure Handling
Timestamp
Snapshot
Aggregation
GitHub Actions
GitHub Pages
```

등을 모두 보여줄 수 있다.

---

# 21. GitHub 후보의 문제

GitHub Events API는 전 세계 GitHub의 모든 이벤트를 하루 단위로 완전히 제공하는 API가 아니다.

따라서:

```text
오늘 GitHub에서 287개의 작업이 발생했다.
```

라고 표현하면 안 된다.

정확한 표현:

```text
GitHub Public Events API
12:00 UTC Snapshot
```

처럼 정의해야 한다.

또한 API 자체에 지연 가능성이 존재한다.

따라서 데이터 정의를 매우 명확하게 해야 한다.

```text
Keyless
```

# 35. Hacker News는 안전 후보

Steam이 실패한다면:

# INTERNET IS TALKING

또는:

# INTERNET HEAT

을 적극적으로 검토한다.

Hacker News는 공식 공개 API가 있기 때문에 기술적으로 비교적 깨끗하다.

# 38. 현재 프로젝트 철학

T04에서 목표는 단순히 API를 잘 호출하는 것이 아니다.

좋은 프로젝트는:

```text
대중적으로 이해 가능

```

# 40. 결론

현재까지 나온 아이디어 중 하나를 억지로 선택하지 않는다.

이번 탐색부터는:

> **“어떤 API를 사용할까?”**

가 아니라:

> **“오늘 세계 사람들이 실제로 무엇을 하고 있는가?”**

에서 시작한다.

현재 가장 탐색 가치가 높은 질문은:

### 🎮 What is the world playing?

### 🔥 What is the internet talking about?

### 📖 What is the world reading?

### 💻 What are developers building?

이다.

최종적으로는 이 중 하나를 **하루 하나의 명확한 숫자**로 압축한다.

그리고:

```text
오늘값
단위
출처
조회시각
어제값
차이
방향
```

을 한 화면에서 15초 안에 이해할 수 있도록 만든다.

**지금은 구현 단계가 아니라 데이터 소스 선별 단계다.**

검증되지 않은 비공식 API나 scraper를 이용해서 주제를 억지로 성립시키지 말고, 글로벌·대중적이면서 공식적이고 재현 가능한 데이터가 발견될 때까지 후보를 비교한다.
