# 대조표 — 원자료 · 저장값 · 계산값 · 화면값

카드 5 가 요구하는 대조다. **손으로 계산해서 화면 결과와 맞춰 본 기록**이다.

마지막 갱신: 2026-08-28

---

## 먼저 — 이 자료는 원자료 재현이 안 된다

정직하게 맨 위에 적는다. 숨기면 카드 1 체크리스트에 걸린다.

Steam 동시접속자는 **부르는 순간의 사람 수**다. 확정된 하루치 집계가 아니다.
그래서 같은 주소를 나중에 열면 **반드시 다른 숫자가 나온다.**

실제로 재 봤다.

| 시각 (UTC) | 값 | 직전 대비 |
|---|---:|---:|
| 2026-08-27 00:04 | 572,811 | — |
| 2026-08-27 00:43 | 551,673 | −21,138 |
| **2026-08-27 00:59** | **551,673** ← 저장된 값 | 0 |
| 2026-08-27 01:27 | 537,072 | −14,601 |

**따라서 "원자료 = 저장값" 대조는 성립할 수 없다.** 대신 성립하는 것을 대조한다.

| 대조 | 가능한가 | 방법 |
|---|---|---|
| 원자료 ↔ 저장값 | ❌ | 순간값이라 다시 잴 수 없다 |
| **원자료 응답 형태 ↔ 저장 구조** | ✅ | 아래 1절 |
| **저장값 ↔ 화면값** | ✅ | 아래 2절 |
| **저장값 ↔ 계산값 ↔ 화면값** | ✅ | 아래 3절 |

이 한계를 화면에도 적어 두었다 — 출처 칸 아래 경고문이 그것이다.

## 1. 원자료 응답 형태 ↔ 저장 구조

**원자료** (2026-08-27 00:59:17 UTC 호출)

```
GET https://api.steampowered.com/ISteamUserStats/GetNumberOfCurrentPlayers/v1/?appid=730
→ {"response":{"player_count":551673,"result":1}}
```

**저장값** (`data/records.json`)

```json
{
  "value": 551673,
  "unit": "명",
  "appid": 730,
  "date": "2026-08-27",
  "sourceUrl": "https://api.steampowered.com/ISteamUserStats/GetNumberOfCurrentPlayers/v1/?appid=730",
  "sourceLabel": "Steam · 동시접속자",
  "sourceTime": null,
  "timezone": "Asia/Seoul",
  "fetchedAt": "2026-08-27T00:59:17.522Z"
}
```

| 항목 | 원자료 | 저장값 | 일치 |
|---|---|---|---|
| 값 | `player_count: 551673` | `value: 551673` | ✅ |
| 항목 이름 | `player_count` | `appid 730` 의 동시접속자 | ✅ 같은 항목 |
| 단위 | 응답에 없음 (사람 수) | `"명"` | ✅ 우리가 붙인 단위 |
| 대상 | `?appid=730` | `appid: 730` | ✅ |
| 출처 관측 시각 | 응답에 없음 | `sourceTime: null` | ✅ 없는 값을 만들지 않음 |
| 조회 시각 | 호출을 완료한 순간 | `fetchedAt` 에 그 순간을 적음 | ✅ |
| 주소 | 위 URL | `sourceUrl` 이 같은 URL | ✅ |

단위는 값의 의미에 맞춰 정의한다. 원천 관측 시각은 Steam이 주지 않으므로 HTTP
`Date`로 대신하지 않고 `null`과 미제공 이유를 저장·표시한다. `fetchedAt`은 우리가
조회한 시각이며 출처 관측 시각과 다른 필드다.

## 2. 저장값 ↔ 화면값

| | 저장값 | 화면값 | 일치 |
|---|---|---|---|
| 값 | `551673` | `551,673` | ✅ (자릿수 구분만 다름) |
| 단위 | `"명"` | `명` | ✅ |
| 잰 날 | `"2026-08-27"` | `2026-08-27` | ✅ |
| 시간대 | `"Asia/Seoul"` | `Asia/Seoul` | ✅ |
| 출처 관측 시각 | `null` | `제공되지 않음 · Steam API 미제공` | ✅ |
| 조회 시각 | `2026-08-27T00:59:17.522Z` | `2026-08-27 09:59` | ✅ UTC→KST 환산 |
| 출처 주소 | `sourceUrl` | 링크가 같은 주소 | ✅ |

**조회 시각 환산 손계산**

```
00:59 UTC + 9시간 = 09:59 KST      (Asia/Seoul = UTC+9, 서머타임 없음)
```

화면 표시 `2026-08-27 09:59` 와 같다. ✅

## 3. 저장값 ↔ 계산값 ↔ 화면값 (변화량)

두 실제 날짜의 대표값을 같은 `appid=730`과 단위 `명`으로 비교한다. 예약 시각
10:10은 목표이며, 아래에는 각 Reading에 저장된 실제 조회 시각을 적는다.

| | 이전 (D−1) | 현재 (D) |
|---|---|---|
| 날짜 | 2026-08-27 | 2026-08-28 |
| 원자료 응답에서 저장한 값 | 551673 | 545528 |
| 저장값 | 551673 | 545528 |
| 실제 조회 시각 | 2026-08-27T00:59:17.522Z | 2026-08-28T01:39:03.092Z |
| KST 표시 | 09:59 | 10:39 |

**손계산**

```
차이   = 545528 − 551673 = -6145 명
방향   = -6145 < 0 → 감소 ▼
변화율 = -6145 ÷ 551673 × 100 = -1.113884…% → -1.11%
```

**화면값**

```
▼ -6,145 명 (-1.11%)
손계산 545528 − 551673 = -6145
```

계산은 `src/view/board.js` 의 `crosscheckRows()` 가 만들고, 그 함수는
`test/board.test.js` 에서 손계산과 같은 식으로 검증된다.

```js
// test/board.test.js
assert.equal(x.hand, '551673 − 500000 = 51673');
```

## 4. 단위가 다르면 비교하지 않는다

`compare()` 는 두 기록의 `unit` 이 다르면 `null` 을 돌려준다. 테스트로 막아 두었다.

```js
// test/records.test.js — '단위가 다르면 비교하지 않는다'
const records = [{ ...rec(...), unit: '천 명' }, rec(..., '명')];
assert.equal(compare(records, 730, '2026-08-28'), null);
```

자료가 부족하거나 단위가 다르면 비교값을 표시하지 않는다.

## 5. 비밀값 0건

이 API 는 인증 키를 요구하지 않는다. 애초에 넣을 비밀값이 없다.

그래도 실제로 훑었고, **걸린 것을 하나씩 확인했다.** "0 건" 이라고만 적으면
검사를 안 한 것과 구분되지 않는다.

| 검사 대상 | 걸린 수 | 정체 |
|---|---:|---|
| `src/` · `scripts/` | **0** | — |
| 빌드 산출물 `dist/` | 1 | React 가 가진 HTML input 타입 목록의 `password:!0`. 폼 입력 종류 열거지 비밀값이 아니다 |
| git 이력 전체 | 13 | 전부 **검사 패턴 자체**다 — `card-check/SKILL.md`(2), `review/SKILL.md`(1), `deploy.yml`(1), 그리고 인증 실패를 시험하는 `test/fetchReading.test.js`(1) 등 |

```bash
grep -rniE "api[_-]?key|token|secret|password" src/ scripts/ --include="*.js" --include="*.mjs"
→ 0 건
```

**네트워크로 나가는 주소는 코드에 박힌 것이 전부 네 개**이고, 그중 실제로 호출하는

```

https://partner.steamgames.com/doc/webapi/ISteamUserStats                               ← 문서 링크
https://github.com/myeongjundev/info-board                                              ← 저장소 링크
```

질의문자열은 `?appid=730` 하나다. 여기에 얹을 비밀값이 없다.
