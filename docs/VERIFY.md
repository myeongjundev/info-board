# 검증 안내서

설치나 로그인 없이 공개 주소에서 확인할 수 있습니다. 실제 데이터는 계속 바뀌므로
특정 날짜나 동시접속자 수를 통과 기준으로 고정하지 않습니다.

## 어디로 가나요

**https://myeongjundev.github.io/info-board/**

## 무엇을 하나요

세 단계입니다.

1. 첫 화면에서 동시접속자 값·단위·잰 날·측정 시각·시간대·데이터 상태를 확인합니다.
2. 아래로 내려 `데이터 품질` 영역에서 `펼쳐서 손으로 대조하기`를 엽니다.
3. 주소 끝에 `?replay=timeout`을 붙여 연 뒤 `다시 시도 · T04-RECOVER-D2`를 누릅니다.

## 무엇이 보이면 통과인가요

### 1단계 — 실제 데이터

- 동시접속자 숫자 옆에 단위 `명`이 보입니다.
- `잰 날`, 실제 `조회 시각`, `Asia/Seoul`, 데이터 상태가 구분되어 보입니다.
- 데이터가 오래됐다면 마지막 정상값과 원래 조회 시각을 그대로 유지합니다.

### 2단계 — 출처와 계산 대조

- Steam 공식 원자료 주소가 보입니다.
- 원자료가 관측 시각을 주지 않는다는 설명과 실제 조회 시각이 따로 보입니다.
- 저장값·이전 저장값·손계산·계산값·화면값이 한 자리에서 연결됩니다.
- 서로 다른 실제 날짜가 둘 이상 있고 같은 날짜가 중복되지 않습니다.
- 원자료 링크의 현재 숫자와 저장된 화면 숫자가 달라도 정상입니다. 동시접속자는
  호출 순간마다 달라지며, 화면에는 저장 당시 조회 시각이 함께 표시됩니다.

### 3단계 — 실패 후 복구

복구 버튼을 누르기 전에는 다음 합성 상태가 보입니다.

```text
stale / timeout · 마지막 정상값 105 pt · 일별 행 1건
```

`다시 시도 · T04-RECOVER-D2`를 누른 뒤에는 다음처럼 바뀝니다.

```text
fresh / none · 120 pt · 일별 행 2건 · 변화 +15 pt
```

이 값은 실제 시장 데이터가 아니라 실패·복구 경로를 검증하기 위한 공개 합성 fixture입니다.

## 안 될 때

- 자료를 못 읽으면 숫자를 새로 만들지 않고 마지막 정상값과 원래 조회 시각을 남긴 채
  `오래된 자료`와 실패 이유를 표시합니다.
- 마지막 정상값도 없으면 숫자 자리에 `—`를 표시합니다.
- 주소에 `?fault=timeout`, `?fault=auth`, `?fault=rate-limit`, `?fault=offline`,
  `?fault=schema`를 붙이면 다섯 장애가 서로 다른 문구로 표시됩니다.
- 화면이 비어 있으면 주소 끝의 `/`와 `?fault=` 또는 `?replay=` 값을 확인합니다.
- 공개 주소가 404라면 [GitHub Actions](https://github.com/myeongjundev/info-board/actions)에서
  최근 `배포`가 성공했는지 확인합니다.
