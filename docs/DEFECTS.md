# 결함 24개 — 무엇이 어떻게 잡혔는가

만들면서 5개, 자체 리뷰에서 8개, 공개 화면을 실제로 열어 보고 3개, 로컬 개발
서버를 띄워 보고 1개, 그 김에 돈 전체 검토에서 1개, 게임을 추가하며 1개, 배포 주소를 처음부터 열어 보고 1개, 사용자가 쓰다가 2개, 대비를 재서 1개, 화면 구조를 다시 짜며 1개를 찾았다. 전부 고쳤고 커밋에 남아 있다.

**여기 없는 것도 있다.** 아직 안 고친 지적은 이 목록에 넣지 않는다 — 고친 것과
섞으면 무엇이 남았는지가 흐려진다. 열려 있는 것은
[검토 기록](../work-log/2026-08-28-검토-88727f7.md) 에 있다.

이 문서를 쓰는 이유는 목록을 자랑하려는 게 아니다. **어떤 결함이 어떤 수단에
잡혔는지** 세어 보면, 설계 결정이 어디까지 지켜 줬고 어디서 뚫렸는지가 보인다.
상태는 [DECISIONS.md](DECISIONS.md) 에 있고 여기는 결함만 다룬다.

## 만들면서 찾은 것 (5)

### 1. 달력에 없는 날짜가 통과하고 있었다 — 현실과 어긋난 검사

`validateRecord` 가 `Date.parse` 로 달력을 검사했다.

```js
Date.parse('2026-02-31')   // NaN 이 아니다. 3월 3일로 굴러간다
```

그래서 그 줄은 **죽은 코드였다.** 앞선 소재(Stack Overflow) 판부터 있던 문제다.
되돌려 찍어 같은 글자가 나오는지 보는 방식으로 고쳤다.

**잡은 것:** 테스트를 쓰다가. 통과할 줄 알았던 경우가 통과했다.

### 2. `seriesOf` 가 정렬하지 않았다 — 조용히 상함

`compare` 와 `movingAverage` 는 "앞엣것이 이전 날" 이라는 전제로 인접 항목을 집는다.
정렬되지 않은 배열이 들어오면 **엉뚱한 날과 비교하고도 조용히 성공한다.**
부르는 쪽을 믿지 않도록 안에서 한 번 더 정렬하게 했다.

**잡은 것:** 테스트. 정렬 안 된 입력을 일부러 넣어 봤다.

### 3. 테스트 개수 가드가 고장나 있었다 — 가드가 고장

`node --test` 는 파일을 못 찾아도 종료 코드가 0 이라 "전부 통과" 와 "아무것도
실행 안 함" 이 똑같이 초록불로 보인다. T03 에서 겪은 일이라 통과 개수를 세는
가드를 넣었는데, **기본 리포터의 통계줄이 `ℹ` 로 시작해 grep 패턴이 빗나갔다.**
가드가 늘 0 으로 읽고 있었다.

TAP 리포터의 `# pass 97` 을 읽게 바꿨다.

**잡은 것:** 가드를 로컬에서 한 번 돌려 봤다. 안 돌려 봤으면 CI 가 계속 빨간불이거나
(막는 쪽으로 실패) 계속 초록불이었을 것이다.

### 4. 화면이 예정 시각을 실제 측정 시각인 양 썼다 — 시각

경고문이 `SOURCE.measuredAtLocal`(매일 재기로 한 시각)을 썼다. 그래서 화면에

```
잰 시각   2026-08-27 09:59
...
위 숫자는 2026-08-27 10:10 에 잰 값이다.     ← 바로 아래에서 다른 시각
```

이 되었다. **이 정보판이 잡으려는 거짓말과 정확히 같은 종류다.** 실제 `fetchedAt`
을 쓰게 고쳤다.

**잡은 것:** 브라우저로 화면을 실제로 읽다가. 코드만 봤으면 못 봤다.

### 5. 마지막 정상값이 없는데 배지가 `오래된 자료` 라고 했다 — 시각

장애 화면은 "정상값이 한 번도 없어 보여 줄 마지막 값이 없다" 고 하는데
배지는 `오래된 자료` 였다. 오래된 값**조차** 없으면 `자료 없음` 이어야 한다.
카드 3 의 "정상값이 없을 때 값이 있는 것처럼 표시하지 않는다" 를 배지가 어겼다.

**잡은 것:** 브라우저. 두 문구가 한 화면에 같이 보여서 모순이 드러났다.

## 자체 리뷰에서 찾은 것 (8)

### 6. 자정을 걸친 실행이 다음 날 값을 버렸다 — 조용히 상함 🔴

`date` 는 시작할 때 한 번 계산해 `assertMeasurableNow` 로 확인받는데,
`fetchReading` 은 **호출마다 그 순간의 날짜를 스스로 다시 계산한다.**
게임 16개를 도는 데 5~8초가 걸린다.

```
23:59:57 시작 → 앞쪽 게임: 2026-08-27
       8초 뒤 → 뒤쪽 게임: 2026-08-28   ← 확인받지 않은 날짜
```

진짜 문제는 그다음이다. 넘어간 값이 다음 날 칸에 **먼저** 들어가고, 다음 날 10:10
정규 실행이 `upsert` 의 first-wins 규칙에 걸려 그 자정 값을 지키고 **진짜 10:10
값을 버린다.** "매일 같은 시각에 잰다" 가 깨지는데 화면에는 아무 티도 안 난다.

`keepDate()` 로 약속한 날짜의 것만 남긴다. `collect.mjs` 안에 두면 검증할 수 없어
`records.js` 로 옮기고 테스트로 막았다.

**잡은 것:** 코드 읽기. 테스트도 화면도 못 잡는 자리였다.

### 7. 화면의 경과 시간이 얼어붙었다 — 시각

`now` 를 로드 성공 때만 갱신해서, 페이지를 열어 두면 **`34분 전` 이 영원히
34분 전**이었다. 자정을 넘겨도 `오늘 잰 값` 배지가 그대로 붙어 있었다.

30초마다 다시 센다. 자료를 다시 부르지는 않는다.

**잡은 것:** 코드 읽기 — `new Date()` 가 불리는 자리를 전부 훑다가.

### 8. `<main>` 랜드마크가 없었다 — 접근성

스크린 리더가 본문으로 건너뛸 수 없었다.

**잡은 것:** 리뷰 점검표.

### 9. 방문자 시계가 뒤처지면 21시간 전을 `방금` 이라고 했다 — 시각

경과 시간은 **방문자의 시계**로 센다. 그 시계가 하루 느리면 기록이 미래에 있는
것처럼 보이는데, 코드가 `ms < 0` 을 전부 `방금` 으로 뭉갰다.

```
시계 하루 느림 → {"ms":-75557522,"text":"방금"}
```

**우리가 알 수 없는 것을 아는 척한 것이다.** 1분까지는 흔한 오차로 두고, 그보다
크면 `이 브라우저 시계로는 셀 수 없다` 고 말한다.

**잡은 것:** 경계값을 일부러 넣어 본 테스트.

### 10. 배지에 `오래된 자료 · -1일 밀림` 이 나올 수 있었다 — 시각

9번과 같은 뿌리다. 기록 날짜가 방문자의 오늘보다 뒤면 `staleDays` 가 음수가 된다.
**밀린 게 아니라 셀 수 없는 것**이므로 `clockSkew` 로 따로 알린다.

**잡은 것:** 9번과 같은 테스트.

### 11. `movingAverage` 가 죽어 있었다 — 죽은 코드

정의되고 **테스트까지 있는데 아무 데서도 쓰이지 않았다.** 앞선 소재에서 넘어온
유물이다. 지우는 대신 화면에 이었다 — 요일 차이 때문에 전일 대비만 보면 노이즈를
정보인 척하게 되는 문제는 소재가 바뀌어도 그대로이기 때문이다. 7일이 안 차면
`null` 이라 지금은 안 보이고 저절로 켜진다.

**잡은 것:** export 사용처 세기.

### 12. 매일 쌓이는 기록이 공개 주소에 안 나갈 뻔했다 — 조용히 상함 🔴

수집 워크플로는 기본 `GITHUB_TOKEN` 으로 커밋한다. 그런데 **`GITHUB_TOKEN` 이
만든 push 는 새 워크플로 실행을 만들지 않는다** — GitHub 이 무한 재귀를 막으려고
그렇게 해 두었다. 그래서 배포 워크플로가 안 깨어난다.

```
저장소의 records.json   매일 늘어남
공개 주소의 records.json  첫 배포 때 굳은 채로 정지
```

내일이면 저장소에는 2일치, 화면에는 1일치가 된다. **카드 4·5 의 통과 기준이
"공개 주소에서 보인다" 이므로 그대로 낙제인데, 사람이 아무거나 push 하기 전까지
아무도 눈치채지 못한다.**

`deploy.yml` 에 `workflow_run` 트리거를 달아 수집 뒤에 배포가 이어지게 했다.

**잡은 것:** 워크플로 파일 읽기. **아직 실제로 겪어 보지는 않았다** — 수집이 CI 에서
한 번도 안 돌았기 때문이다. 문서로 확인한 동작이고 내일 아침이 첫 시험이다.

### 13. `workflow_dispatch` 가 아직 `메울 날짜` 를 광고했다 — 잔재

앞선 소재는 하루치 확정 집계라 빈 날을 나중에 메울 수 있었다. 동시접속자는 그럴
수 없다. **이 프로젝트가 명시적으로 금지한 동작을 UI 가 권하고 있었다.**

입력칸을 없앴고, `collect.mjs` 도 날짜 인자를 조용히 무시하지 않고 거부한다.
값은 멀쩡한데 사람이 잘못 아는 것이 제일 나쁘다.

**잡은 것:** 워크플로 파일 읽기.

## 안 고치고 남긴 것

정직하게 남긴다.

1. **대표 게임만 실패한 날** — 패널이 대표 게임의 최신 날짜를 기준으로 삼아, CS2 만
   실패하면 `날짜별 기록` 은 오늘인데 패널은 어제 것을 보여준다. 16개 중 하나만
   실패할 확률이 낮고, 고치면 "어느 날짜를 보고 있는가" 가 화면마다 갈라져 오히려
   헷갈린다.
2. **`?empty=1` 단독** — `?fault=` 없이 쓰면 아무 일도 안 한다. 빈 상태는 장애와
   함께 보는 것이므로 의도한 동작이다.
3. **크로미움 말고 다른 브라우저에서 보지 않았다.**
4. **12번을 실제로 겪어 보지 못했다.** 고침은 문서로 확인한 동작에 근거한다.

## 14. 통화를 우리가 골라서 1000배 틀렸다

| | |
|---|---|
| 무엇 | 차트 가격이 USD 센트인데 `/100` 후 원화 기호를 붙여 나갔다 |
| 어디 | `src/ui/SalesChartsPage.jsx` · `src/source/salesCharts.js` |
| 얼마나 | `₩70` ← 실제 `₩79,800`. **공개 주소에 나가 있었다** |
| 잡은 것 | **공개 화면을 실제로 열어 원자료와 대조** |
| 고침 | 나눗셈을 없애고 Steam 표기 문자열을 그대로 쓴다 |

**앞의 13개와 다른 점이 둘 있다.**

첫째, **테스트도 리뷰도 못 잡았다.** 값이 형식상 멀쩡했기 때문이다 — 정수였고,
할인율과 앞뒤가 맞았고, 스키마를 통과했다. 틀린 것은 **단위** 하나였고 단위는
코드 안에 적혀 있지 않았다. 화면을 열어 원자료와 나란히 놓아야 보였다.

둘째, **가드를 달 줄 알면서 안 단 자리였다.** 같은 응답의 descriptor 에는
`assertDescriptorsPresent` 를 달아 두고 가격에는 안 달았다. 한 곳에 스키마 가드를
달 이유가 있었으면 같은 응답의 다른 필드에도 대개 같은 이유가 있다.

셋째로, `releaseCalendar` 의 `minorFromWon` 에 **같은 결함이 잠복**해 있었다.
지금은 KRW 로 와서 맞았을 뿐, 미국 러너에서 도는 날 틀렸을 자리다. 하나를 찾으면
같은 모양을 다른 데서도 찾아야 한다는 것이 이 목록 전체의 패턴이다.

근거와 판단은 [DECISIONS.md](DECISIONS.md) 의 `통화를 우리가 고르지 않는다` 절.

## 17. 편의로 둔 미들웨어가 우리 화면을 못 뜨게 했다

| | |
|---|---|
| 무엇 | `npm run dev` 가 백지였다. `#/` 를 포함해 아무 화면도 안 떴다 |
| 어디 | `vite.config.js` 의 `serve-data` 미들웨어 |
| 얼마나 | **개발 서버만.** 빌드·배포본·테스트는 전부 정상 |
| 언제부터 | `238f79b` (2026-08-28 14:02) — `OverviewStrip` 이 들어온 커밋 |
| 잡은 것 | 로컬 개발 서버를 띄운 것. 그 전까지 아무 수단에도 안 걸렸다 |
| 고침 | 목록과 판단을 `src/source/dataFiles.js` 로 내리고 질의 붙은 요청은 넘긴다 |

`records.json` 을 화면이 **진짜로 fetch 하게** 하려고 개발 서버에 미들웨어를 뒀다.
그 미들웨어가 이렇게 골랐다.

```js
const hit = FILES.find((f) => req.url?.startsWith(`/${f.path}`));
```

`238f79b` 에서 들어온 `OverviewStrip` 이 같은 파일 여섯 개를 **ESM 으로** 들여온다.

```js
import salesCharts from '../../data/sales-charts.json';
```

Vite 는 이것을 `/data/sales-charts.json?import` 로 부르고 **모듈로 바꿔서** 돌려줘야
한다. 그런데 `startsWith` 가 그 주소도 잡아 원문 JSON 을 `application/json` 으로
내줬다. 브라우저는 모듈 MIME 검사에서 거절하고, **거절당한 모듈을 부른 화면 전체가
안 뜬다.** 여섯 파일에서 같은 일이 났다.

### 왜 하루 반 동안 안 보였나

셋이 겹쳤다.

| | |
|---|---|
| **개발 서버에만 있다** | 미들웨어는 `configureServer` 다. 빌드는 `closeBundle` 로 파일을 복사할 뿐이라 같은 코드가 아니다 |
| **어제 검증이 전부 빌드 경로였다** | 웹디자인 여덟 커밋을 `VITE_BASE=./ npm run build` + `vite preview` (4173) 로 확인했다. dev 를 한 번도 안 띄웠다 |
| **테스트가 볼 수 없는 자리였다** | 247개 중 `vite.config.js` 를 부르는 것은 하나도 없다. 브라우저 없이는 못 돌리는 코드다 |

**`?import` 를 안 쓰는 동안은 진짜로 멀쩡했다.** `records.json` 은 fetch 로 읽어
질의가 안 붙는다. 그래서 이 결함은 **누가 새로 ESM import 를 쓰는 순간** 태어났고,
그 사람은 화면을 빌드로만 봤다.

### 고침 — 판단을 테스트가 보는 자리로 내렸다

`?import` 만 걸러도 화면은 뜬다. 그것만 하지 않았다. **이 결함의 원인은 판단이
틀린 것이 아니라 판단이 아무도 못 보는 자리에 있던 것**이기 때문이다.

`src/source/dataFiles.js` 에 목록과 `matchDataFile()` 을 두고 `vite.config.js` 는
그것을 부르기만 한다. `test/dataFiles.test.js` 가 네 가지를 본다.

```
/data/records.json         → records.json      화면이 fetch 하는 주소
/data/records.json?import  → null              Vite 가 모듈로 바꿔야 한다
/data/records.json.bak     → null              앞부분만 같은 주소
src 가 들여오는 data JSON 이 전부 목록 안에 있는가
```

옛 `startsWith` 판단을 이 검사에 넣어 보면 **세 줄이 전부 틀린다.**

```
/data/records.json?import       → 옛 판단: data/records.json
/data/sales-charts.json?import  → 옛 판단: data/sales-charts.json
/data/records.json.bak          → 옛 판단: data/records.json
```

`.bak` 은 겪지 않은 결함이지만 같은 한 줄에서 나오므로 같이 막았다.

### 이것은 `view` / `ui` 를 나눈 이유와 같은 규칙이다

[CLAUDE.md](../CLAUDE.md) 구조 절이 `테스트할 수 없는 자리에 계산을 두지 않는다` 고
적은 것은 `src/ui` 를 두고 한 말이었다. **빌드 설정도 같은 자리다.** 오히려 더 나쁘다 —
`ui` 는 스크린샷으로라도 보지만 `vite.config.js` 는 개발 서버를 띄워야만 보이고,
개발 서버는 배포에 안 쓰이므로 안 띄우는 날이 있다.

### 16번과 같은 종류다

16번은 **성격이 다른 두 가지를 같은 `return null` 로 처리**한 것이었다.
17번은 **성격이 다른 두 요청을 같은 `startsWith` 로 처리**한 것이다.

| | 무엇 | 어떻게 해야 하나 |
|---|---|---|
| 화면이 fetch 한다 | `/data/records.json` | **원문 JSON 을 내준다.** 그러라고 둔 미들웨어다 |
| 화면이 import 한다 | `/data/records.json?import` | **비켜선다.** Vite 가 모듈로 바꿔야 한다 |

같은 파일을 부르지만 원하는 응답이 다르다. **한 줄이 둘을 못 가르면, 둘 중 하나는
언젠가 틀린 것을 받는다.**

## 18. 한 화면의 두 패널이 같은 질문에 정반대로 답했다

| | |
|---|---|
| 무엇 | 순위 이동이 어제 저녁 값과 오늘 아침 값을 견주면서 시각을 안 적었다 |
| 어디 | `leaderboard`·`byGenre`·`graveyard`·`rankMovement` — `movers` 만 배치 창을 썼다 |
| 얼마나 | 75줄 중 **59줄**. 공개 주소에 그대로 떠 있었다 |
| 잡은 것 | 결함 17번을 고치다 개발 서버를 처음 띄우고 돈 전체 검토 |
| 고침 | 값은 두고 `measurementSpread` 로 시각을 재서 화면이 밝힌다 |

8/27 기록 75건은 한 번에 잰 것이 아니었다.

```
2026-08-27  09:59 KST  16개
2026-08-27  20:09 KST  59개     ← 10시간 10분 뒤
2026-08-28  10:39 KST  75개     한 배치, 20초 안에
```

`pendingGamesForDate` 가 **그날 빠진 게임만** 채우기 때문이다. 8/27 은 재는 목록을
16 → 75 로 늘린 날이었고, 늘린 59개가 저녁에 채워졌다. 예외가 아니라 목록이 늘거나
일부가 실패한 날마다 되풀이되는 구조다.

### 갈린 자리

`movers` 는 결정 `05a4c05` 대로 5분 배치 창을 적용해 그 59개를 비교에서 뺐다.
**바로 옆 패널 넷은 날짜로만 골랐다.** 같은 화면에서 같은 자료를 놓고 한쪽은
"이건 못 견준다" 고 하고 다른 쪽은 아무 말 없이 견줬다.

CLAUDE.md 3-1 이 실측으로 못박은 그 편향이다 — 같은 날 01:00 → 07:30 사이에 PUBG 는
+214%, HELLDIVERS 2 는 -44% 였다. **방향이 게임마다 반대라 평균으로도 못 지운다.**

### 고름 — 빼지 않고 적는다

`movers` 처럼 빼는 길로 가지 않았다. 두 계산은 성격이 다르다.

| | 무엇을 하는가 | 다른 시각이 섞이면 |
|---|---|---|
| `movers` | 두 값의 **차이를 만든다** | 없는 변화를 만들어 낸다 → **뺀다** |
| 줄세우기·합계·순위 | 잰 값을 **나열한다** | 값은 여전히 참이다 → **적는다** |

빼는 쪽을 골랐으면 8/27 순위가 75개에서 16개로 줄었을 것이다. 그건 그날 잰 것을
우리가 화면에서 지우는 일이고, 이 저장소가 오래된 값을 지우지 않고 오래됐다고
적어 온 것과 반대 방향이다.

그래서 `measurementSpread` 가 그 날짜를 언제 쟀는지 재고, 화면이 이렇게 말한다.

```
두 날을 잰 시각이 다르다. 2026-08-27 는 09:59 ~ 20:09 (10시간 10분에 걸쳐),
2026-08-28 은 10:39 한 번 쟀다. … 아래 59개 줄의 이동에는 하루의 변화가 아니라
잰 시각의 차이가 섞여 있다. 값은 지우지 않고 그대로 두고 그 줄에 시각을 달았다.
```

**한 배치로 잰 날은 아무 말도 하지 않는다.** 실측으로 확인했다 — 실제 파일에서는
순위 이동 패널의 문구 하나와 59개 줄 표시만 뜨고, 줄세우기·장르·오래된 게임은
조용하다(8/28 은 20초 안에 다 쟀다). `fetchedAt` 을 저녁으로 옮긴 사본에서는 넷 다 떴다.

### 문장을 한 곳에 둔다

네 패널이 같은 사실을 말해야 해서 `SpreadNote` 하나만 두고 주어만 받는다.
그러다 **`이 순위은`** 이 나왔다 — 받침에 따라 은/는이 갈리는데 컴포넌트가 조사를
붙이고 있었다. 주어를 조사까지 붙여서 받도록 바꿨다. 화면을 실제로 열어야 나오는
종류라 15·16번과 같은 자리다.

## 19. 화면이 자료가 안 따르는 규칙을 말했다

| | |
|---|---|
| 무엇 | `출시 13년 이상 게임의 현재 접속자` 라고 적어 놓고 9년째 게임이 들어 있었다 |
| 어디 | `src/ui/App.jsx` 의 패널 문구 · `graveyard` 가 고르는 `tier === 'legacy'` |
| 얼마나 | 17개 중 1개(Battlerite 2017). 공개 주소에 그대로 있었다 |
| 잡은 것 | 게임 25개를 추가하며 `tier` 경계를 확인하다가 |
| 고침 | 규칙을 적는 대신 **실제 범위를 세서 적는다** |

`tier` 는 나이 규칙이 아니라 **우리 판단**이다. `definition.js` 도 그렇게 적어 두었다 —
`active 지금 현역 / legacy 나온 지 오래된 게임`. 그래서 개발이 멈춘 Battlerite(2017,
9년)는 legacy 이고, 지금도 현역인 CS2(2012, 14년)는 active 다. **나이로 가른 것이
아닌데 화면만 나이로 가른 척했다.**

```
legacy 17개   9년째 ~ 26년째
active 83개   0년째 ~ 14년째      ← 겹친다. 나이 규칙이었으면 안 겹친다
```

`ageSpan()` 이 그 목록의 실제 범위를 세고, 화면은 이렇게 말한다.

```
이 목록은 나이로 고른 것이 아니라 우리가 오래됐다고 분류한 것이다.
지금 17개가 들어 있고 9년째부터 26년째까지다.
```

**14번과 같은 종류다.** 거기서는 단위를 우리가 골랐고, 여기서는 기준을 우리가 골랐다.
둘 다 값은 멀쩡하고 화면의 말이 틀렸다.

### 곁에서 하나 더

같은 확인에서 `3678970` 의 이름이 `TBH: Taskbar Hero` 로 적혀 있는 것을 잡았다.
상점 표기는 `TBH: Task Bar Hero` 다. 추가한 25개 중 이름이 어긋난 것은 이 하나였고,
연도는 25개 모두 상점 출시일과 맞았다. `definition.js` 주석에 남겼다 —
`594570`·`1049590` 을 잡았던 그 자리다.

## 20. 아직 안 읽은 것을 못 읽었다고 말했다

| | |
|---|---|
| 무엇 | 첫 화면 요약이 로딩 중에 `확인 불가 · 정상값이 아직 없다` 라고 했다 |
| 어디 | `src/view/overview.js` 의 `playingAxis` · `src/ui/StreamingPage.jsx` 의 `0/2` |
| 얼마나 | 공개 주소를 열 때마다. 자료가 올 때까지 |
| 잡은 것 | 배포 주소를 처음부터 열어 본 것. 로컬은 너무 빨라 안 보인다 |
| 고침 | `AXIS.LOADING` 을 만들어 셋이 아니라 넷을 가른다 |

`overview.js` 는 파일 첫머리에 이렇게 적어 두었다.

> `EMPTY` 와 `UNAVAILABLE` 을 같은 `—` 로 뭉개면, 이 판이 잡으려는 거짓말을 요약
> 칸에서 우리가 저지르게 된다. "없다" 와 "모른다" 는 다른 말이다.

**그래 놓고 세 번째 상태를 빠뜨렸다.** `아직 모른다` 를 `못 읽었다` 로 뭉갰다.
`board` 가 `null` 인 것만 보고 왜 `null` 인지는 안 물었기 때문이다 — 파일이 상해서
`null` 인 것과 아직 안 와서 `null` 인 것이 같은 모양이었다.

스트리밍 페이지도 같았다. 읽는 동안 `DATA READINESS 0/2 공식 데이터 연결` 이 떴다.
**연결이 0개인 것과 아직 세지 않은 것은 다르다.**

### 고침

```
읽는 중       읽는 중 · 기록 파일을 읽는 중 · 아직 못 읽은 것이 아니다   흐린 글자
못 읽음       확인 불가 · 정상값이 아직 없다                          붉은 글자
스트리밍      —/2 읽는 중        →  2/2 공식 데이터 연결
```

**네 축 중 이 축만 로딩이 있다.** 나머지 셋은 빌드 때 번들에 들어온 스냅샷이라
읽는 순간이 아예 없다(결함 17번이 그 구조에서 나왔다). 그래서 `loading` 은
`playingAxis` 하나만 받는다.

**값이 이미 있으면 로딩이라도 값을 보여준다.** 새로고침 중에 숫자가 사라지면
그것도 거짓말이다 — 그 값은 여전히 마지막 정상값이다.

### 이 결함의 성격

앞의 19개와 달리 **잠깐 스쳐 간다.** 그래서 로컬에서는 안 보이고 배포 주소에서만
보였고, 개발 서버 응답을 4초 늦춰서야 다시 잡을 수 있었다.
`fetchedAt` 계열(4·5·7·9·10번)이 `언제` 를 잘못 말한 것이라면, 이건 `지금 무슨
상태인가` 를 잘못 말한 것이다.

## 21. 누르려고 다가가면 도망갔다

| | |
|---|---|
| 무엇 | 왼쪽 구획 패널이 펼쳐진 상태에서 아래 동작 버튼으로 커서를 옮기면 패널이 접혔다 |
| 어디 | `src/ui/SectionNav.jsx` 의 `onMouseLeave` · `.secnav.is-compact-open + .symbolrail` |
| 얼마나 | 1600px 미만의 모든 화면. 맨 위로·다시 읽기를 **누를 수가 없었다** |
| 잡은 것 | 사용자가 쓰다가 |
| 고침 | 한 요소의 진입·이탈이 아니라 커서가 둘 중 어디에 있는지를 본다 |

패널은 `<nav class="secnav">` 의 `onMouseEnter` 로 열리고 `onMouseLeave` 로 닫혔다.
그런데 아래 칸의 동작 버튼(`.symbolrail`)은 **그 `<nav>` 의 자식이 아니라 형제**다.
CSS 가 `.secnav.is-compact-open + .symbolrail` 로 위치만 그 패널 안에 겹쳐 놓았을 뿐,
DOM 으로는 남이다.

그래서 이런 고리가 생겼다.

```
커서를 버튼으로 옮긴다
  → <nav> 에서 mouseleave      (버튼은 nav 밖이니까)
  → hoverOpen = false → 패널이 접힌다
  → 접히면 .symbolrail 이 display:none      (펼침 상태에서만 보이므로)
  → 커서 밑에서 버튼이 사라진다
```

**눈에 보이는 한 덩어리와 DOM 의 한 덩어리가 다른 자리**였다. 16번이 성격이 다른
두 가지를 같은 코드로 처리한 것이라면, 이건 같은 것으로 보이는 둘이 실제로는 남인
자리다.

고침은 구조를 바꾸지 않는다. `pointerover` 로 **커서가 `.secnav` 또는 `.symbolrail`
안에 있는지**를 보고 그 값으로 연다. 창 밖으로 나가면 `pointerover` 가 더 오지
않으므로 `pointerleave` 로 따로 닫는다.

실측으로 확인했다 — 나브에 커서(열림) → 버튼으로 이동(**열린 채 유지**) →
바깥으로(닫힘).

## 22. 흐린 글자가 읽히지 않았다 — 어두운 화면에서 55곳

| | |
|---|---|
| 무엇 | 작은 글씨의 대비가 WCAG AA(4.5:1)에 못 미쳤다 |
| 어디 | `--text-faint` 토큰 · `.deal-badge` 처럼 채움 위에 글자를 얹는 자리 |
| 얼마나 | 어두운 화면 **55곳**(4.08~4.45), 배지류 2.28. **배포본도 같았다** |
| 잡은 것 | 라이트 모드를 붙이며 화면의 모든 글자를 잰 것 |
| 고침 | 흐린 글자 토큰을 한 단 밝히고, 채움 위 글자는 `--on-accent` 로 |

**라이트 모드를 만들다 어두운 화면의 문제를 찾았다.** 대비를 재는 도구를 만들고 나니
어두운 쪽부터 걸렸다. 배포본에서 같은 값(55곳·최저 4.08)을 확인했으므로 새로 생긴
것이 아니라 **처음부터 있었는데 아무도 재 보지 않은 것**이다.

두 종류였다.

1. **가장 흐린 글자 토큰이 조금 어두웠다.** `#6f7b8e` 는 카드 위에서 4.38 이다.
   `#8593a8` 로 한 단 밝히니 55곳이 한 번에 넘어갔다.
2. **채움 위의 글자가 채움을 따라가지 않았다.** `.deal-badge` 는 밝은 초록 채움에
   흰 글자(2.28)였다. 채움이 테마를 따라 바뀌므로 글자도 따라가야 한다 —
   `--on-accent` 는 채움이 밝으면 어둡고 어두우면 밝다.

### 이 결함의 성격

앞의 것들과 다르게 **화면을 봐도 안 보인다.** 흐린 글자는 원래 흐리라고 만든 것이라
눈으로는 "의도한 대로" 로 읽힌다. 재야만 나온다. 15·16번이 스크린샷으로 잡힌 것과
반대쪽이다 — 저쪽은 재도 안 나오고 봐야 나왔다.

**재는 자를 두 번 고쳤다.** 반투명 배경을 흰 바탕에 합성해 재서 멀쩡한 5곳이 미달로
나왔고, 테마 전환 애니메이션이 끝나기 전에 읽어 흰 카드가 어두운 화면에 있는 것처럼
나왔다. 그대로 믿고 고쳤으면 멀쩡한 자리를 망가뜨렸을 것이다. 3번(가드가 고장)이
말한 것과 같다 — **만들어 둔 자가 맞는지도 확인해야 한다.**

## 23. 맨 위로 눌러도 맨 위가 아니었다

| | |
|---|---|
| 무엇 | `맨 위로` 단추가 아무 데도 아닌 자리에 멈췄다 |
| 어디 | `SymbolRail` 의 ↑, 구획 나브의 `현재` — 같은 코드가 두 벌 |
| 얼마나 | 매끄러운 이동이 끊긴 자리에 그대로 섰다. 끊기지 않으면 정상 |
| 잡은 것 | 쓰는 사람이 "애매한 위치까지 올라간다" 고 말한 것 |
| 고침 | 보내 놓고 **도착했는지 본다.** 못 갔으면 남은 거리를 즉시 건넌다 |

두 자리 다 `window.scrollTo({ top: 0, behavior: 'smooth' })` 한 줄이었다. 이 한 줄은
**부탁이지 명령이 아니다.** 브라우저는 여러 이유로 도중에 그만둔다 — 사람이 휠을
조금 굴리면 크롬은 그 자리에서 애니메이션을 버리고, 이동 중에 위쪽 내용의 높이가
바뀌면 스크롤 앵커링이 위치를 밀어 놓고, 아예 프로그램이 부른 매끄러운 이동을 하지
않는 창도 있다.

그만두면 목표에 못 간 채로 선다. 단추에 적힌 이름이 `맨 위로` 인 이상 그 자리는
**약속을 어긴 자리**다. 그래서 부탁한 뒤에 확인한다. 나아가지 않으면 마저 앉힌다.
매끄러움은 있으면 좋은 것이고, 도착은 약속한 것이다.

### 감시를 rAF 에 걸지 않은 이유 — 재서 정했다

처음에는 `requestAnimationFrame` 으로 지켜보게 썼다. 미리보기 창에서 눌러 보니
**여전히 안 움직였다.** 재 보니 rAF 가 800ms 동안 **한 번도 불리지 않았다.**
화면을 그리지 않는 창이나 뒤로 밀린 탭에서 rAF 는 멈춘다.

하필 그런 창이 매끄러운 이동도 하지 않는 창이었다. 감시를 rAF 에 걸면
**고장난 자리에서만 감시가 죽는다** — 가장 필요한 곳에서 없는 안전장치다.
`setTimeout` 으로 바꾸니 그 창에서 정확히 0 에 앉았다.

### 이 결함의 성격

3번(가드가 고장)·22번(재는 자를 두 번 고침)과 같은 줄이다. **고치는 것만이 아니라
고친 것이 도는지도 재야 한다.** 첫 고침은 코드로는 맞았고 테스트도 통과했지만,
정작 문제가 나는 환경에서 돌지 않았다. 미리보기 창에서 실제로 눌러 보지 않았으면
"고쳤다" 고 적고 지나갔을 것이다.

## 24. `상세 보기` 를 눌렀더니 방금 누른 카드가 나왔다

| | |
|---|---|
| 무엇 | 첫 화면 요약 네 칸 중 `동시접속` 의 `상세 보기` 가 아무 데도 안 갔다 |
| 어디 | `SERVICE_AXES.playing.href = '#sec-now'` — 요약 카드와 상단 나브가 같이 쓰던 값 |
| 얼마나 | 누르면 **56px 위로** 올라가 그 카드를 다시 봤다. 나머지 셋은 정상 |
| 잡은 것 | 위쪽 네 띠의 순서를 보려고 네 카드의 링크를 하나씩 눌러 본 것 |
| 고침 | 카드가 쓸 주소를 `detailHref` 로 따로 두고 `#sec-focus` 로 보낸다 |

실측이다.

```
동시접속   → #sec-now      y 142 → 86    (-56px)
매출 순위  → #/charts      다른 페이지
할인·무료  → #/sales       다른 페이지
시청 순위  → #/streaming   다른 페이지
```

`#sec-now` 는 `<main>` 자체다. 그 카드는 `<main>` 바로 아래에 있어서 **거기로 가면
그 카드가 나온다.** 띠 머리글은 이렇게 약속하고 있었다.

> 각 지표를 선택하면 **계산 근거와 상세 구역으로 이동합니다.**

### 왜 한 값을 둘이 나눠 쓰고 있었나

`href` 하나로 두 가지 일을 시키고 있었다.

- **상단 나브**: 그 축이 사는 곳. 동시접속은 이 페이지이므로 `#sec-now` 가 맞고,
  나브는 그 값으로 `지금 보고 있는 곳` 을 표시한다.
- **요약 카드**: 그 축의 자세한 자리. 이건 다른 값이어야 했다.

다른 세 축은 둘이 같아도 됐다 — 어차피 다른 페이지로 간다. **그래서 하나로 쓰다가
동시접속에서만 어긋난 것을 아무도 못 봤다.** 셋이 맞으면 넷째도 맞아 보인다.

고칠 때 `href` 를 바꾸지 않은 이유가 이것이다. 바꿨으면 나브의 현재 표시가 깨졌을
것이다. 없으면 `href` 를 그대로 쓰게 두어 나머지 셋은 손대지 않았다.

### 이 결함의 성격

21번(누르려고 다가가면 도망갔다)과 같은 줄이다. **화면을 보는 것으로는 안 나오고
눌러 봐야 나온다.** 카드는 멀쩡히 그려져 있고 링크도 살아 있다. 누르면 화면이
움직이기까지 한다 — 56px 을, 위로.
