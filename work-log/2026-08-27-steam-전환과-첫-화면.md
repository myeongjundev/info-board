## 오늘 발견하고 고친 결함 다섯

숨기지 않고 남긴다. 발견 → 원인 → 수정 → 재검증까지 실제로 했다.

### 1. 달력에 없는 날짜가 통과하고 있었다

`Date.parse('2026-02-31')` 은 `NaN` 이 아니라 **3월 3일로 굴러간다.** 그래서
`validateRecord` 의 달력 검사가 죽은 코드였다. Stack Overflow 판부터 있던 문제다.
되돌려 찍어 같은 글자가 나오는지 보는 방식으로 고쳤다.

### 2. `seriesOf` 가 정렬하지 않았다

`compare` 와 `movingAverage` 는 "앞엣것이 이전 날" 이라는 전제로 인접 항목을
집는다. 정렬되지 않은 배열이 들어오면 **엉뚱한 날과 비교하고도 조용히 성공한다.**
부르는 쪽을 믿지 않도록 안에서 한 번 더 정렬하게 했다.

### 3. CI 가드가 있는데 고장나 있었다

테스트 통과 개수가 0 이면 실패시키는 가드를 넣었는데, 기본 리포터의 통계줄이
`ℹ` 로 시작해 grep 패턴이 빗나갔다. **가드가 항상 0 으로 읽고 있었다.**
TAP 리포터 요약줄로 바꿨다.

### 4. 화면이 예정 시각을 실제 측정 시각인 양 썼다

`잰 시각 09:59` 라고 적어 놓고 바로 아래 경고문에서는 `10:10 에 잰 값` 이라고
했다. 예정 시각(`measuredAtLocal`)을 쓴 탓이다. **이 프로젝트가 잡으려는 거짓말과
정확히 같은 종류**라 실제 `fetchedAt` 을 쓰게 고쳤다.

### 5. 마지막 정상값이 없는데 배지가 `오래된 자료` 라고 했다

오래된 값조차 없으면 `자료 없음` 이어야 한다. 카드 3 의 "정상값이 없을 때 값이
있는 것처럼 표시하지 않는다" 를 배지가 어기고 있었다.

## 막혔다가 풀린 것 둘

### GitHub Pages 가 꺼져 있었다

배포가 `configure-pages` 에서만 멈췄다. Settings → Pages → Source 를
`GitHub Actions` 로 바꾸니 통과했다.

**`GET /repos/.../pages` 는 켠 뒤에도 인증 없이 부르면 404 를 준다.**
켜졌는지 판정하려면 API 가 아니라 배포를 돌려 봐야 한다.

### 멈춘 실행이 concurrency 그룹을 붙잡고 있었다

8/26 수동 실행이 잡을 하나도 만들지 못한 채 `queued` 로 멈췄다. `collect.yml` 이
`group: collect` 를 쓰므로 이후 예정 실행이 그 뒤에 줄을 선다.

**취소가 되지 않는다** — UI 가 `Failed to cancel workflow` 를 낸다. 잡이 배정된
적이 없어 붙잡을 프로세스가 없기 때문이다.

그래서 그룹 이름을 `collect-v2` 로 옮겼다. 빈 그룹이라 그 실행과 무관해진다.
`push` 도 세 번까지 되감아 다시 시도하게 했다 — 배포와 겹쳐 실패하면 그날 기록을
통째로 잃는데, 순간값은 다시 잴 수 없다.

## 하지 말 것

- **`records.json` 을 손으로 채우지 않는다.** 오늘 급상승 화면 렌더를 미리 보려고
  임시 2일치 파일을 만들었는데 **바로 되돌렸고** `git status` 로 확인했다.
  커밋된 기록은 전부 실제 측정이다.
- **`LIVE` 라고 쓰지 않는다.** Actions 가 하루 한 번 받으므로 방문자가 보는 값은
  최대 24시간 지난 값이다.
- **`어제 대비` 라고 쓰지 않는다.** 실제로 견준 날짜를 적는다. 수집이 하루 빠지면
  이틀 전과 견주게 되는데 그때 "어제" 는 거짓말이 된다.
- **문서화되지 않은 엔드포인트를 쓰지 않는다.** 쓰는 것은 하나뿐이다.
- **실패를 0 으로 저장하지 않는다.**
