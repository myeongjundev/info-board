## 이제 이 저장소에 있는 자

고칠 때마다 새 숫자를 고르지 않으려고 자를 하나 세웠다. **여기서 벗어나는 값을
새로 만들지 않는다.**

| | 값 |
|---|---|
| 안쪽 여백 | **24px** (카드·제목 줄), 작은 카드 안쪽은 16px |
| 세로 간격 | 4의 배수. 요약 카드는 24 / 8 / 16 |
| 조작 요소 | **높이 34px · 모서리 6px** |
| 목록 행 | 좌우 24px |
| 색 | `--axis-*` 네 개는 **그 축의 값이 있는 자리에서만** 쓴다 |

**예외 셋은 일부러 둔 것이다.**

- 상태 배지만 알약(999px). 그 줄에서 지금 살아 있는 상태를 말하는 것이 배지뿐이라,
  혼자 다른 모양인 것이 잡음이 아니라 표시다.
- 지역 스위치는 바깥 36px. 테두리로 감싼 분절형이라 안쪽 26 + 여백 4 + 테두리 1 이다.
  낱개 단추와 셈이 다르다.
- 줄 안에 박히는 가격 단추는 28·24px. 34 로 키우면 줄 높이를 민다.

## 무엇이 어떻게 바뀌었나

### 상단 띠

한 줄에 **색이 다섯**이었다. 보라·파랑·분홍 테두리 알약 셋에 초록 배지와 회색 버튼.
모서리도 999 · 8 · 6 세 가지, 높이도 36 · 36 · 42 세 가지.

나브는 값이 아니라 **길**이라 색이 뜻을 갖지 않는다. 셋 다 회색 글자로 두고 축 색은
hover·focus·현재 칸에만 낸다.

```
검색창    668px 빈 막대 → 440px, 돋보기 추가, 42/8 → 34/6
배경      rgba(21,28,38,.84) → --surface-2   (팔레트 바꾸기 전 잔재)
좁은 화면  나브를 display:none 으로 지우던 규칙 둘 제거 → 아래 줄로 내림
```

### 링크 밑줄

밑줄을 **링크마다 따로** 끄고 있어서 새 링크를 만들 때마다 잊었다.

```
첫 화면 링크 178개 중 밑줄 84개
  요약 카드 4개(카드 전체가 통째로) · 게임 표지 76개 · 상단 나브 3개
문장 속 링크는 0개
```

`a { text-decoration: none }` 하나로 **84 → 0**. 밑줄이 뜻을 갖는 자리는 이제
따로 켠다.

### 여백

요약 카드 한 장 안에 **서로 무관한 숫자가 일곱 개** 있었다.

```
안쪽 21/22/19 + 번호 오른쪽 20,  세로 간격 24 / 9 / 17
        →  20/24,  24 / 8 / 16
```

더 눈에 보이는 것은 따로 있었다. **세 구획 다 제목이 카드보다 더 들어가** 왼쪽
모서리에 층이 졌다 (요약 28↔22, 대시보드 28↔22, 데이터 품질 26↔24).

```
제목 열 개의 왼쪽    25 · 25 · 2 · 25 …  →  열 개 모두 25
제목↔본문 어긋남     0 · 0 · 23 · 0 …    →  열 개 모두 0
```

`2` 였던 둘(`측정 이력`·`데이터 인사이트`)은 카드 **밖**에 있는 제목이었다.
그 패턴을 쓰는 곳이 화면에 하나뿐이라 일부러 다르게 둔 것이 아니라 그냥 다른 것이었다.
`25 = 카드 안쪽 여백 24 + 카드 테두리 1`.

### 하위 세 페이지

넘어가면 같은 것이 다르게 생겨 있었다.

```
구획 제목 줄   22/24/19 · 21/23 · 25/26/22   →  24/24/20
조작 요소      42/8 · 39/6 · 36/6 · 31/6     →  34/6
카드 안쪽      15/16/17 · 16/17/18 · 18/18/16 · 25/28  →  16 또는 24
목록 행        스트리밍만 0 26 (좁은 화면 0 17)  →  0 24
히어로         65/40 · 58/34 · 66/38  →  64/40 · 56/40 · 64/40
```

**할인 페이지 검색·필터가 42px/8px 이었다.** 고치기 전 첫 화면 검색창이 정확히
이 모양이다 — 페이지를 넘어와도 같은 손잡이여야 한다.

### 상단 띠 통일

하위 페이지는 `← 전체 현황` 하나에 작은 글자 나브가 붙은 얇은 줄이었다.
첫 화면과 **가구가 아예 달라서** 넘어가는 순간 머리가 통째로 바뀌었다.

`src/ui/SubpageTopBar.jsx` 를 만들어 셋이 같이 쓴다. 같은 워드마크, 같은 34px 나브,
같은 아래 선. 페이지 이름은 워드마크 밑 한 줄로 내려갔다.

**나브에 네 축을 다 넣었다.** 첫 화면으로 가는 길이 `← 전체 현황` 이라는 별도의 말이
아니라 같은 이름의 한 칸이 된다. 첫 화면 나브도 셋 → 넷 —
**화면마다 길의 수가 다르면 그것 자체가 어긋남이다.**

### 네 축의 이름

```
할인 게임 · 판매 차트 · 스트리밍 순위      (처음, 명사)
얼마나 하나 · 뭐가 팔리나 · 뭐가 싸나 · 뭘 보나    (질문형)
몇 명이 하나 · 무엇이 팔리나 · 얼마나 싸나 · 몇 명이 보나
동시접속 · 매출 순위 · 할인·무료 · 시청 순위     ← 지금
```

**네 번 바뀌었다.** `overview.js` 주석에 그 경로와 이번에 질문형을 버린 이유를
적어 뒀다 — 페이지 제목(`무엇이 지금 팔리고 있을까`)이 이미 질문이라 나브까지
질문이면 같은 말을 두 번 한다. **안 적으면 다음에 또 되돌아간다.**

`할인·무료` 에 무료를 같이 적은 것은 남긴다. 그 축은 할인만이 아니라 무료 배포도
세고 카드가 실제로 `무료 1 · 할인 18` 을 띄운다. 이름이 내용보다 좁으면 안 된다.

이름이 바뀌면서 `question` → `label` (CSS 클래스도), 요약 제목
`네 가지 질문` → `네 가지를 잰다` 도 같이 맞췄다.

## 알고 남긴 것

**1. 순위 목록이 페이지의 절반이다.** — 가장 큰 건이고 다음 후보다.

```
측정 게임 순위   3,801px
순위 이동        4,542px
전체            14,960px      →  둘이 56%
```

75개를 다 세로로 나열해서다. **스타일이 아니라 "무엇을 몇 개 보여줄지"의 문제**라
손대지 않았다. 접기 · 상위 N개만 · 더보기 중 고르는 것은 판단이 필요하다.

**2. 카드 2~4 의 글이 카드 1 보다 1px 늦게 시작한다.** 왼쪽 테두리 때문이다.
테두리를 오른쪽으로 옮기면 없어지지만 세 구획의 반응형 규칙을 다 뒤집어야 한다.
1px 은 보이지 않고 뒤집는 비용은 보인다.

**3. 4의 배수를 벗어난 채 남은 것** 은 여러 곳에서 **똑같이** 쓰는 작은 꼬리표뿐이다
(`7px 9px` 배지 등). 어긋난 게 아니라 일정하게 작은 것이라 뒀다.
`.page` 좌우 여백 18px·14px 도 마찬가지 — 네 화면이 같은 값을 쓰므로 넘어갈 때
어긋나지 않는다.

**4. 라이트 모드는 착수하지 않았다.** 토큰은 `:root` 한 곳에 모여 있어서 자리는 있다.
