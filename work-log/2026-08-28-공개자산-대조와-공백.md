```
      ├─ normalized-reading.schema.json · reading-status.schema.json

```

명세 카드 3의 첫 행동이 파일 SHA-256 확인이라 바로 돌렸다.

```
files listed: 17   MATCH: 17   MISMATCH: 0
package_id: aleph-t04-real-information-board-public-contract-v2
contract_version: 2.0.0 · fixture_contract: 1.1.0
```

**17개 전부 일치.** 카드 3의 `남길 것 — 공개 package ID·파일 hash 대조` 에 그대로
쓸 수 있는 증거다. 재현하려면 `asset-manifest.json` 의 `files[]` 를 돌면서
sha256 과 bytes 를 대조하면 된다.

## 2. 채점 방식이 달라진다

정본 규칙을 그대로 옮긴다.

> 35개 조건을 각각 MET 또는 NOT_MET로 전수 판정한다.
> **관측할 수 없는 조건은 추정해 MET로 만들지 않는다.**

우리가 세운 규칙과 같은 태도다. 다만 이제 판정하는 쪽이 우리가 아니다.

fixture 값이 못박혀 있다. 우리 자체 재현 모드의 값이 아니라 **이 값**이어야 한다.

| fixture | 값 | 기대 상태 | 행 수 |
|---|---:|---|---:|
| `T04-NORMAL-D1-A` | 100 | `fresh / none` | 1 |
| `T04-NORMAL-D1-B` | 105 | `fresh / none` · **같은 행 갱신** | 1 |
| `T04-NORMAL-D2` | 120 | `fresh / none` · delta **+15** | 2 |
| `T04-TIMEOUT` | — | `stale / timeout` · 마지막 정상값 105 유지 | 1 |
| `T04-AUTH-401` | — | `stale / auth` | 1 |
| `T04-RATE-429` | — | `stale / rate_limit` | 1 |
| `T04-OFFLINE` | — | `stale / offline` | 1 |
| `T04-SCHEMA-BREAK` | — | `stale / schema_error` | 1 |
| `T04-RECOVER-D2` | 120 | `fresh / none` · `2026-08-25` 신규 행 정확히 1건 | 2 |

상태 어휘도 고정이다. 우리 `FAULT` 이름과 대조하면:

```
freshness   fresh | stale
error_code  none | timeout | auth | rate_limit | offline | schema_error
                              ↑ 우리는 FAULT.SCHEMA (이름이 다르다)
```

**fixture 날짜는 합성 시계다.** 계약서가 명시한다 — 서로 다른 실제 날짜 2건
(C22~C24)을 대신하지 않는다. 그건 여전히 10:10 KST 수집으로만 채워진다.

## 4. 비어 있는 두 곳

### C07 — 출처 시각이 아예 없다

저장 레코드에 `fetchedAt` 은 있는데 원천이 밝힌 관측 시각이 없다.

```json
{"value":5884,"unit":"명","date":"2026-08-27",
 "sourceUrl":"...appid=10","fetchedAt":"2026-08-27T00:59:21.873Z"}
```

`GetNumberOfCurrentPlayers` 는 타임스탬프를 주지 않는다. 정규화 스키마는
`source_time: null` 을 허용하지만, **C07 조건문은 "출처 시각이 표시된다"** 이고
C23 은 `source_observed_at` 을 대조 대상으로 못박는다.

**우리가 README 에서 "잰 날과 잰 시각을 분리했다" 고 쓴 그 둘은 `record_date` 와
`fetched_at` 이다. 출처 시각이 아니다.** 자랑한 자리와 비어 있는 자리가 다르다.

이건 코드 문제가 아니라 소재 선택의 결과다. 판단이 필요하고, **저장 스키마를
건드리므로 fixture adapter 보다 먼저 정해야 한다.** 나중에 바꾸면 adapter 도 같이
손봐야 한다. 떠오르는 길은 셋이다.

1. `sourceTime: null` 로 두고, 화면이 **왜 없는지** 를 적는다.
   규칙 2("없는 값을 만들지 않는다")와 같은 태도지만 C07 판정이 갈릴 수 있다.
2. 응답 헤더의 `Date` 를 출처 시각으로 쓴다. 서버가 응답한 시각이지 값이
   관측된 시각은 아니다 — **다른 것을 같은 것처럼 부르는 셈**이라 규칙 1 과 충돌한다.
3. 출처 시각을 주는 값으로 대표값을 바꾼다. 이 시점에 소재를 또 갈아엎는 비용이 크다.

**정하지 않고 코드를 건드리지 않는다.** 셋 다 근거가 갈리는 자리다.

### C19 — 공개 fixture 재생 경로가 없다

요구가 구체적이다. `stale / timeout` · 행 1건 · 마지막 정상값 **105** 에서
시작해서, `다시 시도` 를 누르고 `T04-RECOVER-D2` 를 재생하면
`fresh / none` · 행 **2건** · `2026-08-25` 신규 행 **정확히 1건** · 저장값 **120**.

현재 `?simulate=` 는 `records.json` 에 오류를 씌우는 것뿐이라 **행을 만들지 못한다.**
`다시 시도` 버튼 자체는 `FaultPanel.jsx` · `HeroValue.jsx` 에 이미 있다.

붙일 자리는 나쁘지 않다. 참조 구현이 필요한 함수 형태를 그대로 보여준다.

```
resetEvaluationState · applySuccessfulReading · applyError · runFixture
```

그리고 꾸러미 README 가 권하는 구조가 우리 구조와 같은 방향이다.

> live adapter와 replay adapter가 **같은 정규화·저장 함수를 호출하게** 구성하면
> 오류 처리만 따로 꾸미는 실수를 줄일 수 있다.

`src/state/records.js` 에 upsert 가 이미 분리돼 있어서, replay adapter 가 같은
함수를 부르게 하면 된다. **참조 코드를 그대로 복사하지 않는다** — 꾸러미 README 도
"그대로 복사해야 하는 라이브러리는 아니다" 라고 적었다.

### 이건 확장이 아니다

지난 기록들이 세운 "확장을 더 늘리지 않는다" 는 여전히 맞다. 다만 **fixture 재생은
필수 조건(C12~C21·C26)의 채점 경로**다. 판매 차트·스트리밍 같은 확장 구역과
성격이 다르다. 가른 표의 오른쪽이 아니라 왼쪽이다.

## 5. 따로 찾은 결함 — 차트 가격이 달러다

공개 주소 `#/charts` 에 붉은사막 Enhanced 가 `-20% ₩70 → ₩56` 으로 떠 있다.
Steam 원본을 직접 불러 대조했다.

```
"final_price_in_cents":"6384000"    "formatted_final_price":"₩ 63,840"
"original_price_in_cents":"7980000" "formatted_original_price":"₩ 79,800"
```

저장값은 `initialMinor: 6999 / finalMinor: 5599`. 원화가 아니라 **USD 센트**다 —
붉은사막 $69.99→$55.99, Palworld $29.99→$20.99, Dead by Daylight $19.99→$7.99.
미국 정가와 정확히 맞는다.

**원인은 수집 위치다.** `cc=KR` 은 차트 페이지의 렌더링 통화를 바꾸지 못하고
Steam 이 **호출한 IP 기준**으로 통화를 정한다. 한국에서 부르면 ₩, GitHub Actions
러너(미국)가 부르면 $ 가 온다. 마지막 `data: refresh Steam sales charts` 가
UTC 23:54 — Actions 실행분이다.

그래서 **한 파일 안에 두 통화가 섞여 있다.**

| 구역 | 값 범위 | 실제 통화 | 화면 |
|---|---|---|---|
| `live.korea` · `live.global` | 263 ~ 6,999 | **USD 센트** | ₩ (1000배 틀림) |
| `weekly.items` · `monthly.items` | 799 ~ 6,999 | **USD 센트** | ₩ (1000배 틀림) |
| `releaseCalendar.*` | 276,000 ~ 8,480,000 | KRW | ₩ (정상) |

출시 캘린더만 맞는 이유는 그쪽이 `minorFromWon` 으로 화면 텍스트를 파싱하기
때문이다. 차트 4구역은 `final_price_in_cents` 를 그냥 `/100` 한다
(`src/ui/SalesChartsPage.jsx:13`, `src/source/salesCharts.js:57`).

`sales-charts.json` 에는 `currency` 필드가 **없다**. `popular-discounts.json` 과
`discounts.json` 에는 `"currency":"KRW"` 가 있어서 이 문제를 안 겪는다.

**`descriptorAvailable` 처럼 스키마 가드가 잡아줄 수 있었던 종류다.** 성인 분류에는
"한 건도 못 읽으면 스냅샷을 덮지 않는다" 를 달아 놓고, 통화에는 안 달았다.
`화면값이 원자료와 일치한다` 를 정면으로 깨는 자리다.

고칠 방향은 **통화를 저장하고, 모르면 아는 척하지 않는 것**이다. 응답에
`formatted_final_price` 가 있어서 통화 판별에 쓸 수 있다.

## 6. 오늘 화면에서 확인한 것

브라우저 pane 이 안 떠서 **스크린샷은 또 못 찍었다.** 텍스트 계측만 했다.

- 메인 페이지 콘솔 오류 **0건**. 대표값 551,673 · `오래된 자료 · 1일 밀림` 정상
- 카드 5 는 의도대로 `비교 준비 중` — 없는 값을 만들지 않는다
- **성인 분류 접기는 실제로 걸린다.** 한국 매출 차트 2건, 화면이 스스로 개수를 밝힌다

```
16 | 성인 콘텐츠 (Steam 분류) | -20% | ₩30 | ₩24 | 상점 ↗
18 | 성인 콘텐츠 (Steam 분류) | -20% | ₩9  | ₩7  | 상점 ↗
```

순위·할인율·가격·상점 링크 유지, 제목 글자와 표지(`imgs: 0`)만 접힘 — 문서의
주장과 일치한다. (다만 이 두 줄의 가격도 5절의 달러 값이다.)

**사소한 것 하나.** 상점 링크 `href` 에 제목 slug 가 남는다
(`.../app/3718190/___Venus_Returns`). Steam 이 상당 부분 마스킹했지만 완전하지는
않다. 링크를 그대로 두기로 한 결정과 충돌하지는 않아서 판단만 남긴다.

## 8. 확인하지 못한 것

1. **스크린샷을 또 못 찍었다.** pane 이 화면에 안 떠서 프레임 합성이 안 되고
   5초 타임아웃으로 실패한다. 배치가 깨지지 않았는지는 눈으로 봐야 한다.
2. **스크롤스파이도 같은 이유로 미확인.** 지난 기록에서 넘어온 그대로다.
3. **로컬 채점기를 못 봤다.** 채점기가 앱을 어떤 접점으로 재생시키는지
   (URL 파라미터인지, 모듈 호출인지) 계약서에 안 적혀 있다. adapter 형태는
   참조 구현에서 유추한 것이다.
4. **통화가 언제부터 섞였는지 안 세어 봤다.** 지금 파일에 두 체계가 있다는 것만
   확인했고, 커밋 이력을 되짚지 않았다.
