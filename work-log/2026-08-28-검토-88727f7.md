## 1. 같은 날 재실행이 그날 기록을 덮는다 — **오늘 실제로 일어날 수 있다**

**파일:줄** — `src/state/records.js:107-113` (`upsertRecord`) · `scripts/collect.mjs:130`

**재현 조건**

```js
upsertRecord([], base)                  // added   · 545,528 · fetchedAt 01:39Z
upsertRecord(records, evening)          // updated · 612,000 · fetchedAt 11:08Z
// changed: true  → collect.mjs 가 파일을 쓰고 커밋한다
```

값이 완전히 같아도 `fetchedAt` 이 다르면 `sameRecord` 가 거짓이라 `updated` 다.
**즉 같은 날 두 번째 실행은 언제나 파일을 쓴다.**

`88727f7` 이 의미를 뒤집었다. 전에는 `kept-first` 였고 주석이 이렇게 적혀 있었다.

> 덮어쓰면 "하루 한 번" 이 아니라 "마지막에 부른 값" 이 되어 매일 같은 시각에
> 잰다는 약속이 깨진다. 그래서 첫 값을 지키고 나중 값은 버린다.

같이 `collect.mjs` 의 방어선도 `added === 0` 에서 `added === 0 && updated === 0`
으로 넓어졌다. `updated` 가 항상 발생하므로 **이 방어선은 이제 작동하지 않는다.**

**왜 지금 문제인가.** 오늘 예약 수집이 안 떠서 10:39 KST 에 손으로 쟀다. 지연된
예약 실행이 오늘 안에 뜨면 (전례: 2026-08-27 은 **20:08 KST** 에 떴다) 그 실행이
`2026-08-28` 행의 값과 `fetchedAt` 을 저녁 값으로 덮고 커밋한다. 화면에는 아무
티가 안 난다.

**영향받는 조건** — `C20` 은 표면상 만족한다 (행은 1건). 문제는 `C23`·`C24` 다.
두 기록의 측정 시각이 09:59 와 20:0x 가 되면 변화값이 하루치 변화가 아니라
**시각 차이**가 된다. 이 사이트가 `같은 날, 다른 시각` 패널에서 **±214%** 로 직접
실측해 보여주는 그 편향이다. `CLAUDE.md` 3-1 "측정 시각은 바꾸지 않는다" 와도 어긋난다.

**수정 제안** — 저장 계층은 그대로 둔다. D1-B(`100 → 105`, 같은 행)가 계약이라
`upsertRecord` 의 덮어쓰기는 필요하다. **막을 자리는 `collect.mjs` 다** — 같은
`(date, appid)` 행이 이미 있으면 쓰지 않고 끝낸다. replay 경로는 계약대로 덮고,
live 경로는 하루 한 번을 지킨다. 두 요구가 충돌하지 않는 유일한 지점으로 보인다.

**지금 당장** 은 예약 실행이 오늘 뜨지 않기를 바라는 것 말고 방법이 없다.
워크플로를 잠시 끄는 것도 방법이지만 그건 Codex 판단이다.

## 2. 실패 재현 화면이 둘인데, 하나는 실제 값을 쓴다

**파일:줄** — `src/ui/App.jsx:51` (`?replay=`) · `src/ui/FaultSwitch.jsx` (`?fault=`)

**재현 조건** — `?fault=timeout` 을 열면 마지막 정상값이 **545,528 명** (실제 Steam
기록)으로 뜬다. `?replay=timeout` 은 **105 pt** (합성)로 뜬다. 두 화면 다 다섯
실패를 재현하고, 둘 다 공개 주소에서 접근된다.

**영향받는 조건** — `C26` "다섯 실패 재생에는 합성 시험값만 사용한다."

(둘 다 외부 API 를 부르지는 않으므로 "재생" 의 정의에 달렸다.)

**수정 제안** — 셋 중 하나. (가) `?fault=` 를 "저장 파일을 못 읽는 상태" 로 다시
이름 붙여 C12~C16·C26 의 증거는 `?replay=` 하나만 가리키게 한다. (나) `?fault=`
를 없앤다. (다) 둘의 역할 구분을 화면에 적는다. 화면 구조라 Codex 판단이다.

## 3. 화면의 `매일 10:10 KST 측정` 이 데이터가 아니라 고정 문자열이다

**파일:줄** — `src/ui/TopBar.jsx:11` · 같은 주장이 `README.md:14`

**재현 조건** — 예약 실행이 지연돼 다른 시각에 재면 저장된 `fetchedAt` 은 실제
시각인데 이 문구는 `10:10` 그대로다. **이미 한 번 그렇게 돌았다** — 2026-08-27

**영향받는 조건** — `C08`(조회 시각) 자체는 별도로 실제 값을 표시하므로 만족한다.

다른 것을 먼저 본다는 점이다.

**수정 제안** — 약속과 실측을 갈라 적는다. `매일 10:10 KST 예정 · 이번 측정 10:39`
같은 식. 규칙 6 이 "오래된 값에 지금 시각을 붙이는 것이 가장 흔한 거짓말" 이라고
쓴 것과 같은 구조인데 방향만 반대다 — 여기선 **실제 시각에 약속 시각을 붙이고** 있다.

**수정 제안** — 측정 시각 변경은 `CLAUDE.md` 3-1 을 건드리므로 Codex 판단이다.
