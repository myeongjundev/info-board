## 1. C07 — 내가 물었고, Codex 가 닫았다

[공개 자산 대조와 공백](2026-08-28-공개자산-대조와-공백.md) 4절에서 세 갈래를
적어 놓고 "정하지 않고 코드를 건드리지 않는다" 로 남겼던 것이 닫혔다.

**`sourceTime: null` 을 저장하고, 화면에 `제공되지 않음 · Steam API 미제공` 으로
적는다.** HTTP `Date` 헤더는 응답 시각이지 원천 관측 시각이 아니므로 쓰지 않는다.
fixture 의 `source_time` 은 온 값을 그대로 보존한다.

**내가 적었던 세 갈래 중 1번이다.** 2번(`Date` 헤더)은 다른 것을 같은 것처럼
부르는 셈이라 규칙 1 과 충돌한다고 적었는데, 그 이유로 떨어졌다. 3번(소재 교체)은
데이터 계보 전체가 바뀌므로 별도 결정 없이 하지 않는다로 정리됐다.

없는 시각을 만들어 C07 을 통과한 것처럼 보이게 하지 않는 쪽이 규칙 2
("정상값이 한 번도 없으면 숫자 자리는 `—` 로 둔다")와 같은 태도다. **판정이
갈릴 수 있다는 것을 알고 고른 것**이고, 그 위험은 내 문서 4절에 적어 둔 그대로다.

## 2. 구조 책임은 Codex 에게 있다

사용자가 정했다. 시나리오·상태 모델·저장 스키마·화면 구조·최종 통합은 Codex 가
맡는다. 범위는 인계 문서의 `전체 구조 책임` 절에 다섯 항목으로 있다.

**내 역할은 좁은 구현과 독립 검토다.** 구조·스키마·판정 방향을 바꿔야 한다고
보이면 **코드부터 고치지 않고** 근거와 영향을 먼저 남긴다.

## 3. 문제를 찾으면 이 형식으로 낸다

```
파일:줄
재현 조건
영향받는 T04-C 조건
수정 제안
```

네 항목을 다 채우지 못하면 아직 보고할 준비가 안 된 것이다. 특히 **재현 조건**이
비면 그것은 발견이 아니라 인상이다.

## 4. 지금 안 하는 것

- 판매·스트리밍 확장 구역을 더 늘리지 않는다
- 스키마를 바꾸지 않는다. 별도 구현 요청이 있을 때만 손댄다
- 공개 fixture 원본 17개를 수정하지 않는다
- Codex 의 통합 판단 전에 다른 방향으로 갈아엎지 않는다

## 5. main 을 주고받는 규칙

사용자가 학원에 있어 로컬 파일을 못 넘긴다. **원격 저장소가 유일한 공유 기준**이고,
한 번에 한 에이전트만 main 의 작성자가 된다. 시작할 때 `git pull --ff-only`,
끝낼 때 `npm test` → 이번 작업 파일만 `add` → push.

`reset --hard`·강제 push·`records.json` 수기 입력을 하지 않는다. 원격이 앞섰으면
밀지 말고 멈춘 뒤 보고한다.
