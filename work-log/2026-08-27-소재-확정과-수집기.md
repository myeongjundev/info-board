## 지금 돌아가는 것

### 파일 구조

```
src/source/definition.js    출처 정의. 다른 데이터로 옮기려면 이 파일만 고치면 된다
src/source/fetchReading.js  값 한 덩어리(Reading)를 가져온다. 장애를 5종으로 구분한다
src/state/records.js        날짜 키, 중복 방지, 손상 격리, 비교, 이동평균
scripts/collect.mjs         Actions 가 돌리는 수집 진입점
.github/workflows/collect.yml  매일 01:10 UTC (10:10 KST)
data/records.json           진실의 원천
```

### 설계 불변식 — 이걸 깨지 않는 게 제일 중요하다

> **화면에 보이는 값·단위·출처·기준일·조회시각은 언제나 하나의 `Reading` 에서
> 나온다. 절대 따로 전달하지 않는다.**

```js
Reading = { value, unit, date, sourceUrl, sourceLabel, timezone, fetchedAt }
```

`date` 는 값이 가리키는 날, `fetchedAt` 은 내가 조회한 시각이다. **이 둘은 다르다.**
자료가 하루 늦게 확정되기 때문이다. 묶어서만 다루면 "값은 새 것인데 시각은 옛 것"
이라는 거짓말이 구조적으로 불가능해진다.

T03 의 "미리보기와 다운로드를 같게 만들지 않고 **같은 것으로** 만든다" 와 같은 발상이다.

### 기준 시간대

**UTC 다.** Stack Exchange 가 `fromdate`/`todate` 를 UTC 유닉스 초로 받기 때문에,
이 정보판이 말하는 "하루" 도 UTC 하루다. KST 로 환산해 저장하면 원자료의 창과
화면의 날짜가 어긋난다. 화면에 이 사실을 적어야 한다.

### 왜 localStorage 가 아니라 저장소 파일인가

카드 4·5 의 통과 기준이 **"공개 주소에서 보인다"** 이다. 브라우저에 저장하면
심사자 화면에는 기록이 0건이다. 저장소에 커밋하면 누가 열어도 같은 기록을 보고,
**git 이력이 그대로 "실제로 매일 돌았다" 는 증거**가 된다. 조작할 수 없는 증거다.

## 오늘 발견하고 고친 결함 둘

숨기지 않고 남긴다. 발견 → 원인 → 수정 → 재검증까지 실제로 했다.

### 1. 변화 없는 날 CI 가 빨간불이 되는 문제

- **증상**: 같은 값이라 파일을 안 건드리고 끝냈는데 종료 코드가 127 이었다.
  `Assertion failed: !(handle->flags & UV_HANDLE_CLOSING)`
- **원인**: `process.exit()` 이 아직 열려 있는 fetch 소켓을 끊으면서 libuv 가
  죽었다. 로직은 멀쩡한데 종료 코드만 엉킨다.
- **왜 문제인가**: 값이 안 바뀌는 날은 정상인데 Actions 가 실패로 뜬다. 그러면
  진짜 실패와 구분이 안 된다.
- **수정**: `process.exit()` 을 없애고 `main()` 이 코드를 돌려주게 바꿨다.
  `process.exitCode = await main()`.
- **재검증**: 변화 없는 실행 → 종료 코드 0.

### 2. 미래 날짜를 0건으로 기록해버리는 문제 — 더 심각하다

- **증상**: `node scripts/collect.mjs 2099-01-01` 을 넣었더니 거부하지 않고
  **0건으로 기록**했다.
- **원인**: 이 API 는 미래 구간을 물어도 오류가 아니라 `{"total": 0}` 을 준다.
  그대로 믿으면 "그날 아무도 질문하지 않았다" 가 된다.
- **왜 심각한가**: **이 프로젝트가 가장 하지 않으려는 거짓말이 정확히 이것이다.**
  값이 없는 것과 값이 0 인 것은 다르다. 카드 3 의 "정상값이 없을 때 값이 있는 것처럼
  표시하지 않는다" 를 수집 단계에서 이미 어기고 있었다.
- **수정**: `assertSettled(date)` 를 만들어 호출 **전에** 막는다. 아직 끝나지 않은
  날은 재지 않는다.
- **재검증**: `2099-01-01` → 거부, 코드 1. `2026-08-26`(오늘, UTC 기준 미완) →
  거부, 코드 1. `2026-08-25` → 정상, 코드 0.

## 하지 말 것

- **문서화되지 않은 내부 엔드포인트를 쓰지 않는다.** 나무위키 `sidebar.json` 과
  KOBIS `.do` 를 그 이유로 떨어뜨렸다. 지금 쓰는 API 는 공개 문서가 있고 키가 없다.
- **실패를 0 으로 저장하지 않는다.** 위 결함 2 가 정확히 그것이었다.
- **`records.json` 을 손으로 채우지 않는다.** 과거 날짜를 몰아 넣으면 "서로 다른
  실제 날짜의 기록" 이라는 요구를 형식만 만족하고 실질은 어긴다. 기다린 기간은
  능동 작업시간에 포함되지 않으므로 손해도 아니다.
- **상태를 적는 문서를 늘리지 않는다.** [docs/DECISIONS.md](../docs/DECISIONS.md)
  하나만 갱신한다. T02 에서 같은 항목이 세 문서에 미시작·미통과·통과로 각각 적혀
  있었던 사고를 반복하지 않는다.

   그리고 커밋 단계의 `git push` 가 통과했는지. 값이 안 바뀌면 커밋 없이 끝나는
   것이 정상이다.
