## 하나만 본다면

**같은 화면의 두 패널이 같은 질문에 정반대로 답하고 있다.**

8/27 기록 75건은 한 번에 잰 것이 아니다. 두 배치다.

```
2026-08-27  00:59 UTC (09:59 KST)  16개
2026-08-27  11:09 UTC (20:09 KST)  59개     ← 10시간 10분 뒤
2026-08-28  01:39 UTC (10:39 KST)  75개     한 배치, 20초 안에
```

`movers` 는 결정 `05a4c05` 대로 5분 배치 창을 적용해 그 59개를 **비교에서 뺀다.**
바로 옆 `rankMovement`·`leaderboard`·`byGenre`·`graveyard` 는 **날짜로만 고른다.**

그래서 지금 순위 이동 패널은 **어제 저녁 20:09 값과 오늘 아침 10:39 값**을 59개나
견주고 있다. CLAUDE.md 3-1 이 실측으로 못박은 그 편향이다 — 같은 날 01:00 → 07:30
사이에 PUBG 는 +214%, HELLDIVERS 2 는 -44% 였다. 방향이 게임마다 반대다.

화면의 공시도 갈린다. `movers` 는 `대표 배치 … → …끼리 견줬다` 와 제외 건수를
적는데, `rankMovement` 는 `basis`(교집합 개수)만 적고 **시각은 한마디도 안 한다.**

### 이건 예외가 아니라 설계상 반복된다

`pendingGamesForDate` 는 그날 이미 저장된 게임을 빼고 **빠진 것만** 채운다.
목록이 늘어난 날이나 일부가 실패한 날은 한 날짜가 두 배치가 된다. 8/27 이 바로
목록을 16 → 75 로 늘린 날이다.

**그래서 아래 게임 추가안을 오늘 실행하면 그 자리에서 재현된다.** 오늘 칸에
10:39 배치 75개와 지금 시각 배치 25개가 함께 앉는다.

## 나머지

### 2. DLC·팩 appid 는 형식상 멀쩡한 0 을 만든다

`GetNumberOfCurrentPlayers` 를 팩 appid 로 부르면 이렇게 온다.

```
ELDEN RING Tarnished Pack        result=1  player_count=0
DJMAX CLEAR PASS : S20           result=1  player_count=0
```

`parse` 도 `validateRecord` 도 통과한다. 그리고 규칙 2(`아무도 안 하는 게임은
진짜로 0 명이다`)가 **오히려 이 값을 지켜 준다.** 팩은 하는 대상이 아니라서
여기서 0 은 참이 아닌데, 0 을 참으로 대하는 규칙이 걸러 낼 자리를 막는다.

`ELDEN RING Tarnished Pack` 은 지금 `#/charts` 한국 매출 9위에 떠 있다. 매출
차트에서 appid 를 끌어오면 이런 것이 딸려 온다.

### 3. 미출시 appid 는 매일 SCHEMA 장애를 만든다

```
NBA 2K27 · EA SPORTS FC 27 · CoD MW4 · WARDOGS   →  result=42
```

`parse` 가 `result 가 1 이 아니다` 로 막는다. 값이 안 들어가는 것은 맞다. 다만
그 상태의 이름이 `응답 형식이 달라졌다` 이고, 이건 **거짓말이다.** 응답 형식은
안 바뀌었고 그 게임이 아직 안 나온 것이다. 매일 4건씩 쌓이면 진짜 형식 변화가
그 잡음에 묻힌다 — 결함 3번(가드가 고장)과 같은 자리다.

### 4. 화면 문구에 75 가 박혀 있다

```
src/ui/SalesPage.jsx:141   추적 중인 75개 게임에서 …
src/ui/SalesPage.jsx:289   고정 목록 75개 기준
src/ui/SalesPage.jsx:291   / 75개 추적
src/ui/SalesPage.jsx:296   / 75개 확인 · 실패 …
src/ui/SalesPage.jsx:348   추적 게임 75개만 확인한다
README.md:42               매일 재는 게임 75개
```

`GAMES.length` 가 진실인데 여섯 곳에 손으로 적혀 있다. **상태를 두 곳에 적으면
갈라진다** 가 이 저장소가 work-log/README 에서 자리를 없애면서까지 지킨 규칙인데,
화면 문구에는 그대로 남아 있다. 게임을 하나라도 추가하면 네 문장이 그 순간 거짓이 된다.

### 5. 로딩 중이 `확인 불가` 로 나온다

배포 주소 첫 로드에서 실제로 보인다. `records.json` fetch 가 끝나기 전 요약
카드가 이렇게 뜬다.

```
동시접속   확인 불가
          정상값이 아직 없다
```

`overview.js` 는 `EMPTY`(정상인데 해당 없음)와 `UNAVAILABLE`(못 읽었다)을 가르는
것이 이 파일의 핵심이라고 적어 두었다. 그런데 **세 번째 상태 — 아직 안 읽었다 —**
가 `UNAVAILABLE` 로 뭉개진다. `board` 가 `null` 인 것만 보기 때문이다.

`없다`와 `모른다`를 가른 자리에서 `아직 모른다`를 `못 읽었다`로 말하고 있다.

**스트리밍 페이지도 같은 모양이다.** 읽는 동안 `DATA READINESS 0/2 공식 데이터
연결` 이 뜬다. 다 읽으면 `2/2` 가 되지만, 그 사이 화면은 두 플랫폼 다 연결이
끊긴 것처럼 말한다. 배포 주소에서 실제로 보이는 상태다.

### 6. 하위 세 페이지는 `view` 없이 `ui` 에서 계산한다

```
SalesPage.jsx:123    평균 할인율 — reduce 후 나눗셈
SalesPage.jsx:126    36시간 넘었는가 — Date.now() 뺄셈
SalesChartsPage:55   출시까지 며칠 — Date.parse 뺄셈 후 86,400,000 나눗셈
StreamingPage:65     표본 시청자 합계 — reduce
```

`view` 에는 `board`·`panels`·`overview`·`gameDisplay` 넷뿐이고 셋 다 대응이 없다.
`ui 는 계산을 하지 않는다` 는 규칙이 **첫 화면에만 적용됐다.** 그래서 이 계산들은
테스트가 없고 손계산 대조도 못 한다.

### 7. `OverviewStrip` 만 ESM import 다 — 결함 17번의 뿌리

배포본은 안 갈라진다. `deploy.yml` 이 수집 워크플로 넷의 `workflow_run` 마다 다시
빌드하기 때문이다(결함 12번에서 이미 막아 둔 자리). 남는 것은 둘이다.

- **dev 에서 옛 값이 뜬다.** 오늘 실제로 겪었다 — 파일은 `Chained Together
  100,045` 인데 화면은 `Escape from Tarkov 39,294` 였고, 하드 리로드로 풀렸다
- **`vite.config.js` 주석과 어긋난다.** `records.json` 을 굳이 fetch 로 두는 이유가
  `import 로 번들에 넣으면 다시 시도가 아무것도 다시 하지 않는다` 인데, 나머지
  여섯 파일은 그 이유를 안 받는다
